# Public archive contract v2

The v1 endpoints and `X-Noyra-Public-Contract: public-contract-v1` remain unchanged. New `/api/public/*` responses use `public-contract-v2`, `Cache-Control: no-store` and the existing 2,000,000 UTF-8 byte ceiling. There is no evidence module, manifest, proof or public export endpoint.

The existing versioned path normalization also supports `/api/v1/public/*` and `/api/v1/admin/public-publications*` aliases. Both public aliases return the v2 data contract; the path version and public projection contract are distinct. These operations and their error statuses are included in the central `service_contract.py` inventory and `openapi.yaml`.

## Routes

- `overview`: display_name, lifecycle `{state, changed_at}`, generated_at, public_diary_count, last_sleep_completed_at, recent/goals/projects (at most 3/2/2 approved public items). HTTP success means the public HTTP service answered; lifecycle is separate. Reasons, fatigue, expenses and diagnostic details are excluded.
- `timeline`, `diary`, `behavior`, `interactions`, `posts`, `goals`, `projects`, `predictions`, `research`, `sleep`, `lifecycle`, `updates`: `{contract, generated_at, items, next_cursor}`. Only timeline allows another `kind`. Query: limit 1–100 (default 20), since/until timezone timestamps, public text search at most 120 characters, status, cursor, id. Invalid/duplicate/unknown parameters return 400.

Each item: id, kind, title, summary, body, status, details, occurred_at, updated_at, provenance. Explicit summaries also include revision. IDs support browser deep links, not cryptographic evidence. Cursor binds subject, category and filters and a timestamp anchor; each page rereads current publication visibility. Changing filters starts a new page. Clients must replace old lists on refresh rather than treat cached withdrawn text as authoritative.

| Kind | Public origin | Details |
| --- | --- | --- |

| behavior | Latest public behavior revision only | tool, public_target, side_effect_summary, resource_summary, redaction_reason |

| post | Published moderated posts; identity/content hash checked | author_label, post_kind |

| goal | Explicit reviewed summary | status, progress (0–1), next_step |
| project | Explicit reviewed summary | status, progress, next_step, phases (title/status), resource_state enum |
| prediction | Explicit reviewed summary | status, probability (0–1), target_at, outcome enum |
| research | Explicit reviewed summary | status, uncertainty, sources (title/HTTPS URL, max 10) |
| sleep | Explicit reviewed summary | status, started_at, completed_at, reason_category enum |

New summary bodies do not come from private view serializers. `provenance=operator_summary` is mandatory and visible. A summary may omit source_id; binding a source checks its subject but does not grant publication permission to its raw fields. Source IDs and admin actor/history/hash never appear anonymously. Text max: title 240, summary 1000, body 20,000 characters. Unicode surrogates/control characters and unsupported structured fields are rejected. Only publication entries matching `status=published` are anonymously readable.

## Publishing and withdrawal

Operator-authenticated `GET/POST /api/admin/public-publications`, and `POST /api/admin/public-publications/{id}/withdraw` use existing session/CSRF controls. Creation needs explicit confirm_public=true, client publication_id and expected_revision=0. Edits need current revision; source/kind cannot be silently changed. An identical retry creates no extra revision. Withdrawal needs the current revision and does not delete private chats, memories or original runtime records. Each change appends immutable operator revision metadata. Nothing is automatically backfilled or published during schema 92→93 migration.

A published text remains downloadable by visitors until withdrawn, and withdrawal cannot erase visitors' copies. The UI explicitly warns before publishing. External links are never fetched by the archive itself. Each research source link is user-approved and must not contain embedded credentials.

Management GET with `?view=management&limit=20&cursor=...` returns `{items,next_cursor}` (maximum 50 per page), including withdrawn summaries and private source identifiers only after operator authentication. No-query GET retains the bounded legacy list. Cookie writes require the existing CSRF token; stale revisions return 409. No publication operation mutates its private source.

List requests return excerpts in `summary` and an empty `body`; query `id` on the matching category to fetch the current full public body. This keeps large diaries from making a whole list exceed the HTTP size limit. A blank id is invalid. Visibility and integrity are checked again for detail requests, so withdrawn summaries cannot be read from a cached list ID.

Status filtering matches exact approved text (maximum 500 characters), including legal legacy custom statuses. Management outcome reconciliation uses `?view=management&id=...` without cursor/limit and returns `{item: object|null}` only after operator authentication. This exact read distinguishes confirmed absence from an unknown network write outcome; clients retain the original ID and frozen payload while uncertain, and never adopt another writer's revision automatically.

Anonymous queries share a 2-second monotonic deadline, 250,000 SQLite VM steps and 128 MB read/decompression allowance across nested overview reads. Text scanning consumes bytes even when no match is returned; ASCII case folding and literal Unicode matching retain SQLite's existing semantics. Read connections enforce query-only and a 250 ms busy timeout. Budget exhaustion returns 503 `public_query_budget_exceeded` with Retry-After; narrow the date/category filters rather than retry indefinitely. Lifecycle reads are local-only, at most two verified archive segments per page and 2,000 verified candidates. Pages can be shorter than the requested limit, including empty filtered pages with a continuation cursor: follow the cursor until it is null. The cursor advances only past verified records, and is bound to the subject, query and time anchor. Unavailable keys/objects or invalid states still return 503. At most two anonymous cold-read requests are admitted concurrently; excess requests get a retryable budget error. Byte limits count logical work, not process RSS; checkpoints are cooperative and cannot preempt a blocked filesystem call.

Immutable revision history has a separate per-subject allowance of 100,000 rows and 32 MB logical metadata payload, with one 4 KB withdrawal reserve per published summary. Publishing/revisions stop at capacity; identical retries remain idempotent and withdrawals remain possible, including for legacy databases already above the new cap. No historical revision is pruned. These are logical admission bounds, not a claim about the entire SQLite file or index size.


## Independent public reading

`GET /public/{kind}/{percent-encoded-id}` is an anonymous, script-free HTML reader, using the same subject, current publication visibility, hash verification and query budgets as API detail reads. Optional `lang=zh|en` selects labels; `theme=system|light|dark` selects CSS appearance and `return` selects an approved archive view (never a URL). Other, invalid or duplicate parameters return 400. Language/theme remain on language-switch and return links; canonical omits these preferences. Ordinary in-site clicks use SPA reading to preserve the in-memory draft and reread the original list batch on return; copied links and new tabs use HTML. Withdrawn/private/unknown records return 404 with no-store, unavailable verified content returns 503, and oversized rendered HTML returns 413. Existing hash detail URLs remain compatible. Standalone pages include item title, description and Open Graph metadata; canonical/OG URL and image require the configured HTTPS public site origin, never the request Host header.

Bodies support escaped paragraphs and up to three leading `#` heading levels with a bounded 100-link contents list. Raw HTML, scripts and embedded images are not enabled. Research references remain approved HTTPS links without embedded credentials and never trigger server-side fetching. This reader does not add evidence or private export endpoints.

With `NOYRA_PUBLIC_SITE_URL`, `/sitemap.xml` returns a sitemap index; `/sitemap.xml?part=home` lists the homepage. Other `part` values are encrypted and authenticated subject/category/slot-range-bound partition descriptors. AES-SIV deterministic authenticated encryption (not a fixed AES-GCM nonce) gives each immutable range stable URLs, including after new records arrive. Routes disclose no raw subject or unchecked boundaries. Partitions always recheck current verified public visibility, list at most 100 records, and share the normal request work budget. Lifecycle shards release decoded segments as they advance and retain the cumulative request budget. There is no 1,000-record site-wide ceiling. The index remains bounded by SQL/time/response limits and 50,000 descriptors. Invalid descriptors return 400; exhaustion returns 503 and overlarge XML returns 413. All responses use no-store. Saved routes never bypass withdrawal checks; new records need a refreshed index. These controls cannot erase external crawler or visitor copies.

HTTP startup initializes the dedicated private `secrets/public-sitemap-keyring.json` only after subject ownership and before accepting requests. Schema 94 migration and source-write triggers maintain append-only routing slots; anonymous reads never generate keys, write the index or migrate directories. Root index reads indexed high-water marks instead of scanning source history. Existing malformed/unsafe key material fails closed and is not regenerated. HTTP restarts and owners with the same data root retain routes. `PublicArchive` used directly without injected keys is an internal development helper with a process-only key, not the production lifecycle contract.

For rolling hosts or managed rotation, set `NOYRA_PUBLIC_SITEMAP_KEYRING_PATH` to an absolute private file containing `{"format":"noyra-sitemap-keyring/v1","keys":["<64 hex characters>"]}`. The first key signs new routes; up to three previous keys accept old routes. Distribute old+new keys to every owner before switching the first key, and keep the compatibility keys for the crawler retention window chosen by the operator. Removed keys invalidate their routes with 400; fetch a new index. Keys are separate from operator, archive and anti-abuse keys, and no key bytes enter diagnostics or URLs. Full encrypted data-root backups include the managed file. Database-only exports and cross-host restoration must separately preserve/rebind this private routing file; restoring an older keyring does not override current withdrawal or hash checks. Never copy these keys into a public backup or a repository.

The machine-readable Web inventory is `PUBLIC_WEB_ROUTE_CONTRACTS` in `service_contract.py`, separate from `APIRouteContract`. Document success is HTML or XML; rejected query 400, missing/private/withdrawn 404, response too large 413, global capacity rejection 429 and unavailable/budget-limited content 503 use the existing boundary. Successful documents and dynamic errors use no-store; no configured sitemap returns 404. The route contracts do not add JSON API aliases or bypass operator authentication.

Routing slots contain identifiers, never bodies. Withdrawals leave tombstone slots and each shard checks the current source qualification and hash. Migration replay appends missing eligible sources without renumbering existing slots. Encrypted backups and subject-scoped runtime exports preserve slots. An offline reconstruction from sources after losing slots must rotate the routing keys and require a fresh index: chronological reconstruction cannot recover historical insertion order or promise the old slot assignments. Do not delete or renumber live slots. Trigger drift remains a schema integrity finding; this index does not certify source truth or resist a root user who rewrites the database.
