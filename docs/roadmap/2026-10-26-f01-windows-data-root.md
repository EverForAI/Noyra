# F01 Windows 持久化数据根修复计划（2026-10-26）

基线：`2dc8fbcc79babce66b4fdaa95a1bad8e637b4f9a`。分支：`codex/fix-f01-windows-data-root`。只实施 F01；F02 暂缓，F03/F04 不在本轮范围。

## 问题与不可突破的边界

生命周期的 DataRoot 没有传入启动器，标准配置从版本工作目录解析 `.runtime/data`。修复须避免既有主体被空目录替代，以及卸载误删版本树内的真实数据。

- 每个子进程单独绑定绝对 `NOYRA_DATA_DIR` 和托管边界变量，不修改父进程环境。标准运行时在创建目录或 SQLite 之前再次检查。
- 已有 DB 走原来的完整性、身份和所有权检查，不在本轮迁移 schema、改主体 ID 或合并数据库。
- 无 DB 时默认拒绝启动。只允许显式 `start -InitializeDataRoot` 在无主体残留的目录创建新主体；这不是旧数据修复入口。
- 安装/数据根须互不包含且路径组件不穿过重解析点。发现安装树中的 `.runtime`、主体数据库/sidecar，或无法安全检查的目录时拒绝改版本和卸载。
- 对旧位置仅探测和阻断，停止/状态仍可用；不自动搬迁、删旧目录、丢弃 WAL、重写主体身份或清空数据库。
- 已运行的 v1 进程记录仍可用原有 PID+路径+启动时间校验停止；不把它当作数据目录已绑定的证据。新记录明确包含数据根。
- 所有递归删除前在同一生命周期锁下再次校验实际绝对目录和旧数据；保留现有 R03 签名/撤销/拒绝回退语义。

## 模块一：子进程与运行配置契约

1. 通过 ProcessStartInfo 的进程专属环境绑定数据根与初始化许可，隐藏子进程窗口。
2. 在运行配置入口校验托管根与环境值相同、路径独立；缺失/空/错误 DB 明确失败，默认不创建新库。
3. 进程记录升级为带数据根的 v2，兼容停止旧 v1，不静默认可旧进程已修复。
4. 验证真实子进程环境、父环境不变、空目录/已有库/环境冲突/多实例，复审后提交。

## 模块二：遗留数据与破坏性操作保护

1. 在任何接管/指针变更之前检查安装树；不跟随链接，隐藏路径亦检查，无法证明安全则拒绝。
2. 状态投影提供稳定诊断；旧数据存在时 start/install/upgrade/rollback/recover/uninstall 都不进入变更。stop/status 保留。
3. 安装器打包新 helper，升级/回滚重复使用同一绝对数据根；卸载停止后再扫描，拒绝删除遗留主体数据。
4. 直接产品入口验证不创建空库、不改指针、保留数据与 stop/status、拒绝 junction/路径重叠，复审后提交。

## 模块三：集成复审与交付

- 原有 Windows 进程身份、包验证、R02、R03 恢复测试和相关运行配置测试回归。
- 真实 Windows 子进程只运行环境报告夹具，不启动生产 Noyra；SQLite 夹具全部临时创建。
- 增加人工旧安装迁移规程：先停止和锁定、备份完整数据与历史密钥、只读核对主体/连续性、还原到外置保留目录、复核后把旧树移到安装树外的保护区；不自动迁移真实安装。
- 每次提交前按暂存区更新公开允许清单/哈希；提交后核对 HEAD。最终工作区干净，不推送/合并/部署。

## 预期修复风险与验收

总体修复风险高，主要由既有数据歧义与升级兼容造成；采用显式初始化、遗留阻断和分模块验收降低风险。测试不声称替代实机发布启动器、BitLocker/ACL/断电验收。最终报告必须列出实际通过/跳过和剩余边界。
