## 模块顺序及验收

1. 工具与回归：按不可变 Git object ID 读取提交或暂存区；明确允许/排除边界；生成清单；导出并核验精确源码 ZIP。验证二进制、CRLF、脏工作区、暂存区差异、非法路径、缺失和新增文件、篡改和重复归档条目。复审后独立提交。
2. 文件范围与防回归：逐项核对未分类文件，补齐运行源码/部署/测试/规范；保留原始证据和设计产物的排除理由；刷新哈希；加入 Windows/Linux 快速检查与正式发布源码包。复审后提交，再以最终提交和实际导出包独立验证。

## 安全边界

- 工具从显式允许清单生成哈希，不自动批准新增路径，不读取私密工作区文件。
- 每个 Git 跟踪路径必须出现在允许清单或带理由的精确排除清单；新文件默认阻断。
- 不允许公开符号链接、子模块、路径穿越和跨平台路径冲突。
- 二进制内容原样读取；文本以 Git blob 为准，不用工作区 CRLF 或手工归一化。
- 校验表自身不自哈希；其内容由 Git 提交及最终包签名固定。
- 历史报告保留其日期和范围，当前发布规则另写；R03 错误统计追加明确勘误。
- 不推送、不合并、不部署；本次完成后本地工作区应干净。
