## 实施记录

### 1. Q03 日志出口（已实现并复审）

统一安装日志记录工厂，httpx 只保留方法、来源站点和状态，httpcore 只保留白名单事件；Noyra 异常只保留类型和栈位置，不传递原始异常载荷。路径、查询、用户信息、原始响应头不进入 handler。工厂可重复安装，保留其他库既有行为。HTTP 公共模块与服务启动入口均覆盖；未改变发送、凭据存储和计费流程。

实际 httpx/多 handler/DEBUG/异常/安装回归 5 项通过，通讯交叉回归 21 项通过（17 项未选），既有脱敏回归 3 项通过。全根 Ruff 检查和 600 文件格式检查通过，新增日志模块、HTTP 公共模块和测试 Mypy 通过。证据：`.runtime/dispatch-q03-first.log`、`.runtime/dispatch-q03.log`、`.runtime/dispatch-q03-redaction.log`。复审保留站点与状态诊断价值；此措施保护新日志，不清除历史日志，也不把用户自定义 handler 的额外字段视为已审计的网络日志合同。

### 2. Q01/Q02/Q07 通讯（已实现并复审）

消息与令牌交换共享每次调用固定的授权闭包，在令牌锁之后、缓存命中时和发送头之前核验租约、通道、接收绑定、私密推送同意、配置与凭据摘要。缓存按凭据隔离且替换旧条目。令牌请求从锁等待开始计算绝对截止时间，使用 stream 和既有有界读取。保存已确认供应商回执后才拒绝失效任务后续行为；不确定结果不自动重发，撤销授权的失败耗尽重试预算。没有修改入站身份、消息正文、数据库 schema 或删除合同。

首次交叉回归 83 通过、4 失败（旧测试依赖 PermissionError 错误码，已保留兼容性）；随后通道/迁移/HTTP/SMTP/对账 52 通过（6 未选），最终新增故障注入 33 通过，覆盖三家 token、锁/连接等待、停用/凭据更换/失效、已发回执/unknown/刷新、超大响应、缓存与锁截止时间。初轮包含入站身份和私密推送回归。模块 Ruff/format/Mypy 通过；证据 `.runtime/dispatch-transport.log`、`dispatch-transport-cross.log`、`dispatch-transport-final.log`。复审未发现阻断；最终发送检查以 httpcore 的请求头事件为边界，已发送后不能撤回，也不宣称实现真实平台送达验收。

### 3. Q04 浏览器（已实现并复审）

浏览器搜索入口和发头事件核验运行租约；每次请求冻结并核验路由设置版本，配置变更后拒绝旧请求。仅已开始行动的终态结算使用 accounting_scope，成功结果保存后再拒绝失效任务；失败/unknown 返回真实状态，幂等重放不重新搜索，小时预留没有绕过。没有增加禁用开关或改变既有路由优先级含义。

新增故障注入、研究全模块和 HTTP 边界共 47 通过（`.runtime/dispatch-browser.log/xml`），覆盖暂停/隔离/迁移/关闭/路由变更、已发成功/失败/unknown/取消、入口失效、幂等及小时预算。模块 Ruff/format/Mypy 通过，复审终态旁路未包裹新预留或后续研究，不留 executing；没有真实 Bing 请求。

### 4. Q05/Q06 钱包（已实现并复审）

固定准备前策略版本和付款尝试身份，在最终发送核验版本、策略摘要、执行摘要和当前限额。策略写入与付款发送共用数据库旁的一个稳定进程锁；顺序为运行 gate → 进程锁 → 短数据库操作，网络期间不持有 SQLite 事务。HTTPS 与本地 RPC 实际 worker 继承授权闭包，在发头前取得边界，发体完成即释放，不等远端响应；调用线程不持 gate 等 worker，避免互锁。绝对 deadline 从排队前开始，取消/超时后发头和发体钩子拒绝迟到请求。同步自定义 signer 仍在整个调用边界内串行化。

已准备但政策撤销且确定未发的新尝试记失败；unknown 重试仍保持 unknown/原哈希、nonce 和费用预留。运行失效保守结算 unknown 再抛出，替代 signing 残留；已发广播/unknown/失败的终态记账可完成。没有放宽付款、发布门禁，也没有迁移 schema。锁文件固定一个且不包含秘密；默认网络写超时继续约束已进入写入阶段的线程，暂停不能撤回已经发出的请求。

既有付款/本地签名/费用/审计 103 通过；首批新增故障注入 13 通过；补充并发写体、取消、审计、发布门禁、奖励工作流与 HTTP 57 通过，均无失败。全根 Ruff/format 604 文件通过，钱包及新测试/HTTP Mypy 通过。证据 `.runtime/dispatch-wallet-first.log/xml`、`dispatch-wallet-fence.log/xml`、`dispatch-wallet-cross.log/xml`。复审锁顺序、稳定文件身份、独立 worker 收尾和 unknown 不释放均符合预期；真实 KMS/链和 Linux 进程锁验收仍由 E01 覆盖。
