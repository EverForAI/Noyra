# 私密删除原型审计与发布限制

schema 87/88 是 M06 的内部基础设施，不是已经交付的彻底删除功能。管理台没有删除按钮，HTTP 契约没有删除接口。本文件记录可验证范围与阻断项，防止把局部测试误当成整个模块完成。

## 已验证的内部范围

- 同主体会话必须提供明确确认与有效 revision，意图重复提交沿用已有任务。
- 接受意图前进行有界只读预检；来源不明、在途调用和未审计派生域不接受意图，不隐藏原窗口。
- 支持清除没有未审计派生内容的简单会话，包括消息、决定理由、模型输入输出副本、独有记忆全部修订和向量。
- 保留计费、消息关联、原内容哈希和无正文删除收据。必要证据保留不等于保留原文。
- 记忆追加合法归档修订；数据库保护禁止复活内容、重新启用记忆或插入迟到向量。
- 删除围栏阻止新提交、私密上下文提交和新模型授权。终态账本结算继续保留费用，迟到模型响应使用清除标记。
- 已撤回事件与已清除记忆不能成为新的因果来源；未知调用核对同样清除迟到响应及私密审计理由。残留验证在内容事务内执行，失败回滚并记录可重试失败。
- 投递在供应商令牌获取／刷新之后、每次消息 POST 前重查；SMTP 在认证后重查。等待令牌期间撤销联系人、停用渠道或删除内容均阻止新消息请求。已进入网络发送的请求仍有第三方接受或未知结果边界。
- 文件标记先于数据库意图持久化，解决接受意图附近的数据库／文件中断窗口。标记不含会话标题、聊天正文或 API 密钥。
- 加密恢复先验证备份，再重放当前标记；不能重放时不发布恢复目录。没有标记的备份保持原 schema。
- 混合来源记忆仅在存在早于任何被删输入、且由同主体独立事件支撑的原始修订时重建；新记忆不沿用污染 ID，原记忆全部修订及向量清除，归档状态保持。事后更换来源不能证明独立性。
- 启动恢复按主体重放已接受任务及孤立标记，在运行恢复、导出和认知准入之前完成；恢复失败停止准入。不存在的窗口标记不占用任务批次，避免饿死后续真实任务。

## 阻断完整交付的事项

1. 历史反思没有完整私密来源：无法由调用名称可靠判断哪些独立事实属于被删除窗口。必须建立审阅／重新验证路径，不能猜测来源或全量删除其他事实。
2. 没有可验证独立历史修订的多来源记忆仍拒绝删除。不能通过猜测重写或事后换来源来宣称其他事实独立。
3. Appraisal、心理快照、关系、信念、目标、思考、自我模型等丰富派生域尚无完整清除与完整性契约。当前预检拒绝存在这些记录的主体。
4. 来源记录目前覆盖交互／反思直接消息输入，不覆盖全部间接记忆、状态和后续模型输入。必须形成传递闭包并验证并发围栏。
5. 导出作业存在时拒绝删除，尚未实现取消发布、退休下载产物、清理 staging 与残留缓存。
6. 已实现启动续跑，但尚无运行期间后台工作器、公开任务进度接口和全域残留验证；内部运行仍是有界的同步原型。

## 恢复和物理删除限制

恢复防复活依赖最新标记可访问。恢复到另一台没有最新标记的主机不能获得此保证。旧离线备份、SQLite 空闲页／WAL、已下载导出、供应商和通讯平台副本有独立边界。本原型不声明这些副本物理不可恢复，也不声明能够删除 QQ 或供应商历史。

## 下一步验收

先解决上述六项，再开放受鉴权和 CSRF 保护的预检、确认、进度与重试接口；删除期间显示准确阶段和失败原因，所有受保护检索与投递必须排除内容。新增跨域、混合来源、断电续跑、导出竞态及备份恢复回归。通过后才能将 M06 改为完成并继续下一模块。
