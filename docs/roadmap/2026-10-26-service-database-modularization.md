# 服务与数据库模块化实施计划

## 基线与范围

基线为 2e9d2572e559ae7b449e7eafae4ee6964b0a9583。PR #22 尚在检查，独立分支从已审计候选继续，不改写该 PR，也不等待或绕过检查。用户授权本地分模块实施、复审与提交；本轮不推送、不部署。

目标是降低职责集中造成的修改风险。模块化不改变 HTTP 协议、鉴权/CSRF、速率限制、Webhook 签名、准入租约、恢复例外、主体隔离、账本、SQL/迁移版本及关闭顺序。最新审计 A01–A06 不在本轮中混修。

## 模块顺序

1. 固定路由及架构行为基线：盘点入口、边界顺序和已有回归，补真实实现上的有界属性/状态序列测试。新增依赖非必要，不以简化模型替代真实对象。
2. HTTP 按域拆分：先静态/公开读取，再管理读取与业务分发/处理；入口保留路径规范化、鉴权、准入及生命周期特殊规则。服务公共类/导入接口保持。每批搬移用 AST 对照与真实 HTTP 回归核实。
3. 数据库按责任拆分：先原样移动 schema/历史迁移定义与哈希工具，保留 Database 外观和原导出。历史 SQL、指纹、迁移序号及执行事务保持，迁移/备份/恢复编排不与定义移动一并重写。用新旧定义逐项校验及真实历史库升级/失败恢复验证。
4. 明确装配与生命周期边界：在入口和业务模块形成清晰边界后，评估独立提取配置/纯辅助函数；只搬移具有清晰依赖、能证明等价的部分。启动锁、准入、取消/排空和释放顺序本轮保持原执行结构；不为减少行数重写状态机。
5. 维护说明、架构依赖约束、完整复审及交付。README 链接真实维护与响应说明；安全报告以 SECURITY.md 为准，不虚构第二维护者或响应承诺。

每模块完成后：定向回归、跨模块检查、差异复审、更新公开清单、独立提交。遇到不兼容优先缩小拆分边界，禁止放宽业务断言/安全检查以适配拆分。

## 验收

- 路由路径/别名、先后优先级、状态码、响应字段、Cookie/缓存/CSP/错误处理不变。
- 架构性质覆盖主体隔离、身份权限、重复请求、暂停/恢复代次、取消不发布及迁移保真；确定性同步验证并发关键位置。
- 所有历史迁移表达式、SQL 与结构指纹一致，兼容导入仍可用。无新 schema 版本，无生产数据操作。
- 禁止路由业务模块运行时反向导入 service；无动态执行源码、星号转发或大型 Mixin 伪拆分。
- 运行相关 Python/前端回归、Ruff、格式、Mypy；最终校验公开 Git blob 清单和导出 ZIP。已知基线失败单独记录，禁止宣称未执行的 CI/平台门禁已通过。

## 风险

HTTP 搬移与导入补丁位置为中风险，数据库迁移编排与生命周期重写为高风险。采用原文搬移、显式依赖和保留兼容外观控制风险；高风险执行算法保持原样。每个模块独立提交，可逐个回退。
