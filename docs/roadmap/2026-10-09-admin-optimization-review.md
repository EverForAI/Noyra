## 3. 全后台共用的体验规则

- 保持现有品牌和管理台风格，以紧凑列表、表格、标签页和独立编辑区为主；减少长表单、重复卡片、多层嵌套和过小文字。
- 参数使用长期可见的标签、单位和有效值；问号图标按钮打开解释框，说明用途、影响、示例及特殊值。支持键盘、手机、关闭和焦点返回。
- 状态使用中文，技术错误码保留在详情；成功、失败、等待、结果未知、暂无数据与加载失败分别表达，不能只靠颜色区分。
- 时间默认按浏览器本地时区展示，保留 UTC 和时区入口；区分发生、完成、刷新、重试、计划唤醒及预算重置。
- 列表按需加载和有界分页；提供筛选、局部重试、更新时间与实际覆盖范围。一个接口失败不清空整页，旧请求不覆盖新筛选结果。
- 保存与保存后的读取分开反馈。超时或响应丢失时先回查结果，写操作使用幂等或版本检查，避免误重发和覆盖。
- 刷新、切换和关闭保护未保存输入；私密草稿默认仅存页面内存，退出登录清除，不自动写入浏览器持久存储。
- 只读刷新不调用模型、不发送平台消息、不访问链上 RPC、不清理数据；有副作用的操作明确名称、范围及预算影响。
- 验证桌面、窄窗口、手机、软键盘和浏览器 200% 缩放；关键内容不重叠、不被截断，布局不因加载或标签变化跳动。

## 4. 各模块方案与验收

### M01 认知资源

**目标效果**

- 用经济池、深度池两个标签页管理，默认显示启用资源；提供停用、删除、全部筛选及名称、模型搜索。
- 列表显示名称、模型、状态、优先级、可用密钥和额度摘要；新建与编辑采用一致的独立面板。
- 基础连接、调度、每日限制、价格与重试、密钥管理分别成组，每个参数有帮助按钮。
- 尝试次数、输入 Token、输出 Token、美元成本四项每日上限独立开关，可任选组合；关闭表示没有该项资源级每日上限，零额度表示不可使用，不表示无限。
- 旧资源保留原有限制；未提交的字段保持原值。全部关闭时明确提示影响，其他任务、池级和系统限制仍按有效策略执行。
- 新建时即可设置限制；展示已用、预留、剩余和 UTC 重置时间。输入与输出价格采用美元／百万 Token，区分未知价格和确认免费。
- 提供停用、启用、删除资源、追加密钥、撤销单个密钥和清理进度。地址、模型或池变更采用替代资源流程，保持历史调用身份。

**安全边界**

- 资源删除禁止新调用并清理密钥，保留历史调用、费用和无秘密审计；资源删除与会话内容删除是不同语义。
- 在途调用的迟到结果和费用仍需正确结算，不能复活已撤销资源或密钥。清理未完成时如实显示待处理。
- 可选限制须有正式持久策略和迁移，不能用超大整数伪装无限；策略异常不能默认为无限，也不能清空已发生用量。
- 预算授权、预留、结算保持事务和并发保护；配置页面及日志不回显密钥。

**验收重点**：四项限制的 16 种组合、零额度、并发预留、跨 UTC 日期、重试和未知结果计费；停用与删除区别、迟到回调、密钥清理重试、同名重建、重启配置不复活、未保存输入保护。

### M02 模型与搜索用量

**目标效果**

- 支持当天、最近 3 天、7 天、30 天（1 个月）、90 天（3 个月）、全部，默认最近 7 天。
- 当天从所选时区零点开始；其余建议按明确的滚动时间窗查询，返回实际起止、时区、最早可用数据和更新时间。统计时区不改变 UTC 日预算规则。
- 分别显示逻辑调用、实际尝试、重试、成功、失败、未知结果、输入与输出 Token、已知与估算费用；说明调用成功率与尝试成功率的区别。
- 搜索按 API、模型、浏览器和等待分类，显示状态及有证据的等待原因；提供资源、池或供应商明细筛选和分页。

**安全边界**：由鉴权汇总接口统计，约束查询负载；同一次尝试不重复计费。全部指仍可查询的全部历史，不能把截断结果或缺失历史称为全量；无价格、无用量数据不冒充免费。

**验收重点**：六种区间、UTC 与本地日期、跨区间重试、空数据、历史覆盖、重复聚合和大历史查询；切换不重置预算、不影响未保存配置。

### M03 供应商健康

**目标效果**

- 以资源名称、所属池、模型、脱敏供应商主机作为标题，内部 ID 收进详情；经济池、深度池、搜索分别查看。
- 当前健康状态与历史成功率分开：正常、近期失败、冷却中、可尝试恢复、正在恢复探测、结果未知、暂无调用数据。
- 显示统计时间窗、成功／失败／未知次数、延迟、最近成功／失败、错误类别、冷却截止和恢复条件。
- 将凭据权限、限流、连接或响应异常、供应商错误、输出格式等类别转换为有证据的操作建议，并链接到对应资源和活动日志。
- P50／P95 说明样本覆盖和估算口径；快速失败不代表服务响应良好，配置存在也不代表已经调用成功。

**安全边界**：刷新与筛选只读；主动测试必须是单独动作并说明可能计费，复用预算和单探测保护。不能按失败率猜测密钥无效，不能清除历史或强制标记恢复，不展示 URL 凭据。

**验收重点**：无数据、旧失败与新配置区分、冷却结束但未探测、探测租约、未知结果、错误分类、停用历史与局部接口失败。

### M04 数据保留与清理

**目标效果**

- 增加可保存的保留设置及帮助，显示环境默认或已保存策略来源、实际生效版本、下一次计划执行与等待原因。
- 提供健康聚合保留天数、搜索限速记录保留小时数、每批删除上限、自动清理间隔、清理运行历史数量、旧模型内容压缩年龄。
- 原默认值作为兼容起点：30 天、2 小时、500 行、24 小时、100 次、90 天。具体允许范围在实现前核对，搜索必要窗口不低于 2 小时，每批派生行删除上限不超过 500。
- 压缩模型内容保留账本、引用、哈希、预算与幂等证据，不命名为到期删除模型调用。
- 保存策略与立即执行清理分开；缩短保留期或清理前显示预估范围和影响，实际结果列删除、压缩、历史裁剪、跳过和失败。
- 修复 `[object Object]`、只读更新误报保存、重复计数及 HTTP 200 下部分失败误报完成。
- 必要证据容量和磁盘容量独立展示，列出接近上限的表及阻断原因。

**安全边界**

- 普通年龄清理只处理允许的派生数据，不能删除必要模型、行为、搜索和审计证据来解除上限。
- 策略版本、清理快照及续跑游标一致；重启不覆盖已保存设置，恢复备份后不沿用失效游标。
- 普通保留清理与 M06 经明确操作的会话隐私删除使用不同契约；后者需要正式的内容清除及完整性规则。

**验收重点**：参数范围、并发更新、缩短期限、预览与执行差异、部分失败、事务回滚、中断续跑、重启恢复和受保护表不可被普通清理删除。

### M05 生命周期与活动日志

**目标效果**

- 新增活动日志入口，按运行事件、生命周期、模型与搜索、行为执行、管理审计查看；支持时间、类别和状态筛选、分页及暂停自动刷新。
- 展示当前阶段、进入时间、持续时长、上次活动时长、休眠触发原因类别、计划唤醒、循环冷却及下次重试条件。
- 用时间线关联状态转换、模型请求、认知等待、动作和交流；空闲心跳、调度成功、模型成功、回复生成分别表达。
- 让用户能判断等待来自资源缺失、预算、供应商问题、反思尚未完成、完整性或安全暂停，并能进入关联详情。
- 专项审计资源压力更新时间、睡眠判断顺序、故障资源下的反思等待、未知调用隔离和失败退避。按资源设置请求时限及更细错误分类作为待验证方案，有证据并通过审计后才确定运行逻辑改动。

**安全边界**

- 已提供历史证据表明某次短暂活跃由重复失败压力触发；不能据此认定当前所有问题均由该原因造成，也不能直接归因于主机性能。
- 不用延长超时、强制活跃、清空压力或绕过预算代替诊断。恢复资源不保证立即唤醒或立即回复。
- 复用鉴权运行摘要，默认不展示私密正文、完整模型输入输出和反思内容；浏览器不获得任意 shell 或服务器文件读取能力。

**验收重点**：休眠原因和时间关联、正常阶段切换与异常区分、旧压力、跨日预算、反复休眠、分页与脱敏；运行逻辑改动单独回归，不能只凭页面显示判定已修复。

### M06 私密交流、多会话与记忆删除

**目标效果**

- 微信式结构：聊天列表、当前对话、底部输入框；手机在列表与对话间切换。本人可确认的消息标为“我”，实际出站消息统一标为“Noyra”。
- 支持新建、命名、重命名、置顶、归档和删除会话；同名窗口使用独立 ID，不误合并。
- 按时间从旧到新展示、日期分隔、真实回复引用、分页加载历史、复制、跳到最新、状态筛选和有界历史搜索。
- 页面可见时有界增量刷新，错误时退避；阅读历史保留位置并显示新消息提示，切换窗口取消过时请求和隔离草稿。
- 清楚区分已记录、等待处理、调用中、等待资源、接受、暂缓、拒绝、选择沉默、有回复和异常；没有执行证据不显示假已读或假打字动画。
- 发送使用固定幂等键和服务器消息 ID；提交成功与随后读取失败分开，输入法组合不误发送，失败保留草稿。
- 同一经确认交流身份的全部窗口共享授权原始历史检索和长期记忆。未被提取为记忆的旧聊天仍可检索；不在每次请求中塞入全部历史，不承诺每轮准确回忆全部细节。
- 旧网页记录迁入历史对话，保留正文、时间、决定和证据。原固定 `web-user` 是共享管理邮箱，作者不明的历史不能自动标为当前本人或自动授给新关联 QQ 身份。

**彻底删除的最终含义**

- 按用户已选要求，删除窗口、双方聊天原文和相关记忆；不能以归档、隐藏或单纯逻辑删除代替。
- 范围包括本系统保存的关联输入输出副本、摘要、索引、向量、派生记录、导出缓存和草稿。先建立来源追踪，再执行清除；新增历史索引或记忆功能必须同时设计删除能力。
- 会话独有记忆删除；多来源记忆移除被删来源，并根据剩余独立来源重新验证或重建，既不能残留被删内容，也不能误删其他会话的独立事实。
- 删除开始即阻止该会话新提交、上下文检索、记忆提取和尚未发送的投递；在途模型、迟到回复、索引和导出任务不能写回内容。
- 用可续跑的删除任务显示范围、进度、失败和重试；完成约定清除并验证检索无残留后才报告完成。审计只保留必要的无正文数量、任务和结果，不留会话标题及私密理由。
- 旧备份、SQLite WAL／空闲页、已下载导出、QQ 与供应商副本有独立边界。不得把在线清除说成所有副本物理不可恢复；备份恢复流程需保留并应用最新删除标记，防止恢复已删除内容。
- 如需要保证物理不可恢复，需要补充内容加密、存储和备份设计；本次首先明确并验证本系统内容清除范围及外部限制，不宣称自动删掉平台历史。

**安全边界**：会话、作者、参与者、检索、摘要和投递均按真实身份与场景授权；共享历史不扩大其他联系人或群聊权限。正式迁移和受控删除契约必须兼容既有哈希、引用和完整性规则，不制造假回复或改变 Noyra 的交流决定。

**验收重点**：历史迁移、真假回复关联、幂等、迟到更新、多标签页、手机滚动、跨窗口检索、作者归属；删除期间并发、独有与多来源记忆、派生内容、断电续跑、备份恢复和完整性验证。

### M07 通讯渠道、QQ 验证与统一聊天

**目标效果**

- 通讯页面负责接入、联系人、连接和投递；日常聊天进入 M06。按实际平台能力提供独立向导，不用一个通用表单猜字段。
- QQ 官方机器人向导以名称、App ID、App Secret 为主，使用官方接口默认值；回调地址、平台权限和凭证状态分步展示。
- “入站账号绑定”改为“允许谁与 Noyra 聊天”。点击关联我的 QQ，在机器人私聊发送一次性验证码，后台从已验签事件识别身份，再由管理员确认。
- 推荐验证码 10 位 Base32、5 分钟有效、每挑战最多 5 次失败；不要求普通用户查找 OpenID。验证不调用模型，休眠时也可完成接入控制。
- 分别显示凭证、回调、准入、最近入站、处理、回复生成和平台投递；“已启用”不等于每一环节都可用。
- 已准入 QQ 的真实消息和回复在管理台统一查看，保留来源、私聊／群聊和投递状态；不复制为新的交流邀请。
- 经本人验证的私聊可与本人网页身份关联，并选择使用哪个逻辑窗口；切换只影响后续消息，不改写历史。
- QQ 来源回复默认回原 QQ 私聊；网页来源回复默认留网页。可选“将此窗口的 Noyra 新回复也发给我的 QQ”默认关闭，启用时明确私密内容外发范围。

**安全边界**

- App ID／Secret 证明机器人配置控制权，不证明具体聊天者身份，仍需验证码、平台验签、作用域与最终确认。
- 群、频道、其他联系人独立身份和上下文，不把群 ID 当成本人，不按昵称自动合并记忆。
- 验证码单次消费、来源和机器人绑定、限制速率；不进入普通聊天、记忆或正文日志。联系人验证不授予升级、转账或配置管理权限。
- QQ 官方回调按平台实际 HTTPS 与权限要求检查；不能承诺填写 IP 就可接通。NapCat／OneBot 不伪装成现有官方接入能力。
- 默认不补发全部网页历史，未知投递先核对；解绑、停用和删除阻止后续外发，保持事件去重、消息幂等和转发防回环。

**验收重点**：免手填 ID 全流程、码过期重放、跨机器人抢绑、群短码、并发确认、历史归属、平台权限、重复回调、超时与未知投递、取消关联及删除后不复活；使用模拟平台，真实测试限定在明确选定账号。

### M08 钱包采集与付款管理

**目标效果**

- 顶部显示最近观测、过期目标、采集队列、RPC 预算和付款阻断摘要；正文拆为余额观察、余额采集、网络与资产、RPC 预算、赏金与账本、付款与链上执行、审计记录七个分区。
- 只加载摘要和当前分区，列表有筛选、总量／覆盖范围、分页、独立错误和更新时间；技术 ID、租约和尝试详情按需展开。
- 金额按资产小数位精确转换为可读金额与符号，详情保留最小单位原值；未知精度不猜测单位，不用浮点数计算资金。
- 余额明确是已保存快照，区分零余额、无快照、临近过期、过期、未来时间异常和读取失败。
- 分开页面刷新、排队、链上读取、取消、重试、签名广播及恢复；说明何时消耗 RPC 和预算，展示窗口、预留、剩余和重置时间。
- 自动付款策略显示实际有效门槛：模式、启用、暂停、单笔／每日上限和白名单，保存前生成可读变更摘要。
- 将误导性的“退款”改为“释放失败订单的内部预留”，只在后端允许且订单确认为失败时出现，明确不能追回链上资金。
- 未知交易突出查询回执和人工核对；恢复未完成记录说明范围与状态影响，不能当成刷新。

**安全边界**

- RPC URL 的用户信息、路径中的凭据、查询参数和片段需按实际来源脱敏；主机与可确认安全的路径摘要才可显示。私钥、助记词和签名凭证不进入浏览器。
- 页面改造不自动启用付款、不放宽金额或白名单、不广播交易。真实资金操作不属于本轮界面回归。
- 未知结果不能当失败释放资金，也不能盲目重试；允许重试时核对最新状态、金额和收款地址，显示重复付款风险并记录确认理由。
- 钱包状态转换、幂等、双重记账、审计和签名隔离由服务端执行，前端隐藏按钮不是保护机制。

**验收重点**：特殊资产精度、零／缺失余额、凭据脱敏、预算耗尽、并发领取、取消竞态、策略版本冲突、结果未知、重复执行、回执与恢复对账；使用模拟 RPC 和签名器，不向真实网络自动广播。

### M09 公共发帖、容量与图片验证码

**目标效果**

- 独立设置单篇正文长度上限，建议首版 1 至 20,000 字符，默认保持 20,000；前后端统一计数，公开输入显示已用与上限。
- 将原字节上限改名为全部帖子文字存储总额度，使用可读 KB／MB／GB 输入，显示已用、剩余和包含的帖子状态。
- 总容量与单篇长度分开。建议总容量支持低于 1 MB，例如 100 KB；建议首版范围 1 KB 至 2 GB，保留现值，具体范围及十进制单位作为本稿待审决策。
- 降低限制只约束后续提交，不截断或删除已有内容；低于当前已用量时说明暂不能接收新帖。
- 保持标题、正文和署名限制、请求体、队列、频率、审核和总容量的不同含义；保存与刷新失败分开，连接失败文案不统一归咎 HTTPS。
- 完全取消语音／音频验证码，包括前端播放器、切换、后端签发、生成器、素材和相关契约；明确拒绝新音频请求，短期已有挑战按原有效规则处理。
- 重新设计清楚的字形、间距、对比度和轻量干扰，取消遮挡字符主干的粗线；保持宽高比和手机可读尺寸。
- 后台醒目选择纯数字、纯字母、字母与数字混合，保持 6 位。建议新建默认纯数字，既有配置不自动变更；字母不区分大小写并排除混淆字符。
- 公开响应仅提供模式和长度等安全信息，输入键盘随实际模式变化；换图或验证失败保留投稿草稿，防止乱序图片与挑战 ID 错配。

**安全边界**：验证码过期、尝试次数、一次消费、来源绑定、签发限流及审核保持有效；图片清晰不代表能独立阻止所有自动投稿。答案不进入 DOM、元数据、文件名和日志，匿名用户不能自行选择较弱模式；管理员模式切换不误拒绝尚有效的旧挑战。

**验收重点**：中英文、emoji 和组合字符长度一致；恰好上限、超限、直接 API、降低额度后的历史；三种验证码多批合成样本的真实尺寸可读性、旧挑战、音频拒绝、移动键盘、乱序刷新和草稿保留。

### M10 公开生命周期与历史行为

**目标效果**

- 中文展示当前生命周期、更新时间；明确行为列表为历史记录，列出发生或完成时间、结果及准确类别。
- 当前状态与记录发生时的状态分开，不用当前休眠状态回填历史，也不因休眠清空记录。
- 只有可信的当前执行证据才显示正在执行或当前无活动；历史列表本身不能证明在途状态。
- 状态与行为局部加载，避免刚刷新页面被误读为刚执行行为。

**安全边界**：公开页只使用批准的公开字段，不展示私密原因、心理状态、模型内容、会话、密钥和管理诊断。

**验收重点**：活跃与各休眠阶段、历史持续可见、跨阶段排序、独立加载失败、公开投影与私有日志隔离。

### M11 版本维护与运行防护

**目标效果**

- 已安装版本、远端可用版本、升级通道、部署组件和检查时间独立展示；远端错误不清空本地版本。
- 区分暂无正式 Release、连接错误、GitHub 限流、组件缺失和状态读取失败，给出对应处理入口。
- 历史服务器记录中 main 为 200、正式 Release 为 404，解释为当时 stable 来源无可用正式发布；本轮不把该历史结果当实时状态。
- 运行防护子接口分别加载并局部重试；保存成功、刷新失败、登录失效、HTTP 错误和浏览器连接失败分别表达。

**安全边界**：暂无正式 Release 时不偷偷切到 main，不绕过现有来源和发布验证；组件检查按 systemd 实际路径，不能因为旧误查路径缺失就启动重装。浏览器不获得任意部署命令执行能力。

**验收重点**：Release 404／限流／离线、当前版本保持、组件缺失、旧版本兼容、局部 503 与重复提交；本轮方案不自动发起升级。

## 5. 建议实施顺序

按依赖和风险分阶段推进。每个模块完成审计再进入下一模块，模块内的高风险子阶段也需单独复审；本表不表示当前已开始执行。

| 阶段 | 内容 | 进入下一阶段前的条件 |
| --- | --- | --- |
| 0 | 基线与合同：核对源码、生产 SHA、schema、有效配置；整理受保护数据、接口和迁移计划 | 隔离副本可运行，备份可恢复，生产与本地差异清楚 |
| 1 | 共用体验与诊断基础；M05 日志和只读生命周期、M11 错误与版本显示 | 数据来源准确，脱敏、局部失败和旧接口回归通过 |
| 2 | M01 认知资源，随后 M02 用量、M03 供应商健康 | 密钥和预算审计通过，新旧额度兼容，统计不误计费 |
| 3 | M09 公共发帖与验证码，随后 M10 公开状态 | 投稿和验证码控制有效，显示清楚，公开投影无隐私扩张 |
| 4 | M04 数据保留与清理 | 持久策略、保护白名单、恢复与中断续跑验证通过 |
| 5 | M06 会话、历史检索及受控删除 | 先设计来源和删除合同，再建新索引；迁移、隐私清除及恢复均通过 |
| 6 | M07 通讯向导、本人验证、统一聊天及可选推送 | 身份与群私聊隔离、幂等、撤销和投递审计通过 |
| 7 | M08 钱包各子分区依次整理 | 每步金额、预算、状态机和模拟执行审计通过，无未知资金风险 |
| 8 | M12 总览集成与全后台浏览器回归；收尾经证据确认的运行问题 | 页面数据一致、无新越权或副作用、无阻断性回归 |

M05 的调度与时限改动另做审计，不与只读日志第一阶段捆绑。M06 和 M07 共用会话、身份、来源与删除设计，避免各自建设不同消息系统。M12 最后集成，避免首页先显示尚不存在的统计和管理能力。

## 6. 每个模块的审计交付

每个模块需留下实现范围、变更记录和审计结论，至少回答以下问题：

1. 安全边界和预期行为是否与本稿一致？管理员写入、公共读取、主体和参与者权限是否有效？
2. 新旧接口、数据库结构、完整性、已有数据和有效配置是否兼容？有迁移时是否验证中断与恢复？
3. 秘密、私密原文和敏感 URL 是否在页面、日志、错误和导出中受控？
4. 并发、幂等、迟到结果、部分失败、断网、重启、配置冲突和未知结果是否正确处理？
5. 涉及预算、金额、删除和外发时，是否有与风险相符的测试和证据？
6. 桌面与手机完整流程是否可用，帮助是否准确，未保存输入和已加载内容是否保留？

审计结果使用“通过”“通过但有明确非阻断事项”“未通过”。权限越界、秘密泄露、重复付款或计费、历史丢失、预算绕过、删除内容复活、迁移或完整性损坏均阻断后续实施与发布；修复后重新审计。非阻断事项写明影响及处理计划，不能以笼统“无问题”代替证据。

## 7. 发布、恢复与观察

- 按模块保留可审阅的提交和测试证据，正式发布使用明确候选 SHA，不把开发目录直接覆盖生产运行目录。
- 所有 schema 变更使用正式迁移并逐步验证结构合同；在当前生产版本与旧 schema 的隔离副本演练，特别回归此前 schema 71 到 80 的升级链。
- 发布前创建并验证当前数据的加密备份，不用升级前旧备份冒充当前数据保护。恢复方案明确代码、数据库、有效配置和删除标记的兼容边界。
- 不将回退代码链接等同于可安全回退数据库。发生问题时先保留证据，按已演练的兼容路径处理，不随意恢复旧备份丢失新数据或复活已删除会话。
- 验收包括版本、live／ready／health、完整性、数据库、资源预算、消息、存储、恢复单元、服务重启；主机重启及手动解锁按已明确的维护窗口执行。
- 建议发布后先进行约 30 分钟短观察，再进行一次 8 小时 soak；查看运行中的任务和既有结果，避免因误贴启动命令重复创建任务。旧版本 soak 不能代替新候选验收。
- soak 需检查失败探针数量、时间、原因和恢复情况，不能仅看到 `soak=passed` 就宣称零故障。反复、持续或无法解释的就绪降级，schema／完整性故障及服务异常重启需修复后复验。
- 真实平台消息测试、付费模型测试和任何真实钱包交易各有明确目标与范围，不能由浏览器回归或后台刷新自动触发。正式 Release 发布及生产升级按最后确认的发布范围执行。
