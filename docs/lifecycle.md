# Noyra 生命周期协议

## 1. 生命周期状态

```text
booting
orienting
active
winding_down
reflective_sleep
deep_sleep
waking
paused
stopped
resetting
```

## 2. 启动

启动时 MUST：

1. 验证身份和数据库；
2. 读取最后一致状态；
3. 检查未完成的外部行动；
4. 恢复事件队列；
5. 恢复预算和疲劳；
6. 写入 `boot` 事件；
7. 进入 `orienting` 或 `active`。

启动不得重复已经完成的外部行动。

## 3. 活跃

活跃周期可以处理：

- 用户交流邀请；
- 公开互联网事件；
- 内部定时心跳；
- 目标和预测到期；
- 帮助请求结果；
- 工具结果；
- 资源和疲劳变化。

所有处理都必须经过事件账本。

## 4. 睡眠触发

睡眠可以由以下条件触发：

- 工作疲劳达到阈值；
- 预算接近耗尽；
- 连续失败或无信息重试；
- 长时间没有新信息；
- 目标冲突；
- Noyra 自主判断需要整合；
- Noyra 自己的作息周期。

## 5. 睡眠阶段

### `winding_down`

- 停止创建新的外部行动；
- 完成或取消可中断行动；
- 保存工作上下文；
- 写入睡眠开始事件。

### `reflective_sleep`

- 汇总事实和结果；
- 整理记忆；
- 检查矛盾和过时信念；
- 复盘情绪和心境；
- 检查重复重试；
- 修订、暂停或放弃目标；
- 生成候选人格和使命变化；
- 生成公开日记候选。

### `deep_sleep`

- 停止模型调用；
- 停止外部行动；
- 保留事件队列、计时器和状态接口；
- 保存检查点；
- 等待计划唤醒或允许的系统事件。

## 6. 唤醒

唤醒时 MUST：

- 读取睡眠后的状态版本；
- 检查睡眠提交是否完整；
- 读取允许的队列事件；
- 重新计算资源和疲劳；
- 记录唤醒原因；
- 不自动恢复已经失败且无新信息的旧策略。

普通用户消息只能成为唤醒邀请，不能强制语义回复。

## 7. 暂停与停止

- `paused`：保持身份和状态，不处理认知事件；
- `stopped`：停止所有运行，但保留完整数据；
- 用户可以请求暂停和停止；
- 紧急安全事件可以强制停止；
- Noyra 可以记录反对、请求解释或要求延迟，但不能阻止基础设施级紧急停止。

## 8. 重启、迁移和重置

- 普通重启：同一主体；
- 跨机器迁移：同一主体，必须完整迁移身份和状态；
- 模型更换：同一主体，记录认知组件变化；
- 并行复制或分支：新主体 ID；
- 重置：封存旧主体，创建新主体，默认不读取旧私人数据。

## 9. 版本和检查点

每次睡眠、迁移、重启恢复和重置都必须写入状态版本。快照可以恢复，但外部行动账本不能回退。
