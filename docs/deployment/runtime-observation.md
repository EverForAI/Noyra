# 轻量运行观测与后台状态解释

## 范围

`GET /api/v1/admin/runtime-summary` 需要 operator（或有同等权限的管理员）认证。
这是只读、有限样本的运维展示，不是新的就绪门、计费账本、供应商探测或自动恢复指令。
原有 `/health/live`、`/health/ready`、认证 readiness、`/api/diagnostics` 和详细用量接口仍保留。
安全准入和付款授权不读取此摘要，缓存不能使安全检查失效。

## 采集边界与成本

- SQLite 独立只读连接；锁等待最多 100ms，SQL progress-handler 工作预算 250ms。
  这是可中断的查询预算，不是涵盖操作系统文件 IO 的硬实时保证。
- 最近最多 100 次逻辑调用和最多 500 次尝试，明确标注截断和起止时间。
- 结果未知的行动、模型调用、付款及未收口的投递按主体读取，每类最多显示 50 项并标记更多。
  这些提醒不局限于最近调用样本，避免旧未知付款被新调用覆盖。
- 数据库/WAL 仅 stat，磁盘仅读取剩余容量，Linux RSS 仅读取本进程页统计；不递归遍历数据目录、
  不扫描密钥、不执行 quick_check，不访问外部供应商，不产生验证性模型调用或支付。
- 同一观察器串行合并采样，最多缓存 2 秒，锁忙等待最多 50ms 后返回 503。
  摘要标注采集时间和缓存年龄；查询失败返回 unavailable/null，不伪装成零费用、零积压或健康状态。
- 不输出提示词、对话、模型响应、供应商请求 ID、密钥、账户地址或交易原文。

## 指标口径

- 认知启用状态由实际运行服务提供“认知循环是否已创建”的只读视图；不从 HTTP 层不存在的字段或仅有 gateway 配置推断，也不代表供应商已经验证可用。
- 最近循环成功：仅说明记录中的某次循环完成，不保证每条消息被阅读或回复。
- 近期未成功：超过 `max(180秒, 活动间隔×3)` 的展示提醒，**不是故障判定**；长任务可能仍在执行。
- 休眠/唤醒、暂停、停止和循环冷却分别解释，不统一归为掉线或崩溃。
- 模型成功/失败/未知、Token、费用均是有限样本，不是今日总额；完整预算继续由原有用量和资源管理负责。
- 费用保持整数微美元的十进制字符串，浏览器沿用 BigInt 格式化。缺失费用和含估算调用单独标注，
  不能把部分已记录费用当成真实供应商账单，也不能用零估算作为免费证明。
- P50/P95 来自样本中有有效创建/完成时间的逻辑调用，使用 nearest-rank；包含排队与重试，
  不是纯供应商网络延迟，不代表完整历史或未来响应时间。
- 文件大小和可用容量不证明加密、权限、完整性或备份恢复通过。

## 后台入口

总览仍请求四类信息：公开状态、轻量运行观测、生命周期、近期活动；不再默认运行完整诊断。
页面显示判断依据、下一步入口、最近成功、下次重试（循环冷却）、样本和资源范围。
“模块启用”“供应商成功过”“当前供应商可用”“消息已回复”不混为一个状态。
完整性/加密卷/备份等仍需进入运行防护和对应详细页面核对，不能将总览无提醒解释为全部门禁通过。
部分接口失败时保留旧摘要并显式提醒；退出后和旧会话迟到响应不能恢复私密内容。

## 验证与限制

本地单元、HTTP 鉴权、SQL 锁/预算、精确金额、部分失败、会话竞争及页面检查均使用独立测试数据。
首台生产实例未被本次开发修改。本功能不新增数据库 schema 或后台循环，不调整预算、并发、睡眠、
付款自动化及身份/目标逻辑。真实 Ubuntu/systemd、LUKS、异机恢复与长期 soak 仍应按八项门禁执行。

## 认知等待与资源分组补充

- model_sample.by_resource 按资源组、池、模型聚合最近调用样本，不是按密钥的供应商账单。
  分开显示成功/失败/未知/执行中、管理员测试；未出现在样本里的资源不等于已验证或零历史调用。
- unknown_call_reasons 仅分组已记录的有限错误码，未知代码归为其他，不输出原始异常。
  历史约 60 秒耗时不能被解释为供应商未执行/未计费；不会为了诊断发起重试。
- waiting_sample 区分未发现终态证据的等待、终态业务残留、历史取消和父业务缺失；最多 100 条，
  有截断标记，不代替全量审计。处理流程见 cognitive-wait-maintenance.md。

## 保存前与保存后模型测试

草稿探测用于验证尚未持久化的端点与候选思考参数；保存后的测试通过正式网关，
受生命周期、资源授权、预算和当前调用状态限制，最多一次尝试，不自动切换资源。
当前正式测试保持原有 64 Token 输出上限，草稿推理探测的额度可能更大；本轮不扩大付费额度。
提示明确区别配置字段错误、休眠限制、资源停用、授权、预算和输出格式不符合要求。
测试成功只证明该次测试，不证明自主认知流程完成；深度池没有正式调用时仍属于未实测。

## 重试等待期间取消的调用终态

`model_calls.status=failed` 且 `error_code=model_retry_cancelled` 表示：上一尝试已返回或失败并完成本地结算，调用在等待下一次发送时被取消，没有发出下一次请求。这不是供应商故障或免费调用的证明；已付费的无效输出、估计用量和未知用量保留仍按原尝试记录计入预算。调用会写完成时间，重启不把它再次误判为执行中断。

请求执行中被取消仍记为 `unknown / model_call_cancelled`，不自动重试或释放保留。同一个物理幂等键的失败调用不会被网关自动重放；资源路由后续的新显式请求继续按原有规则处理。历史结果未知及其人工重试授权仍有独立隔离与证据要求，不能用取消退避来消除过去的未知尝试。

本修复不批量重分类已经积累的历史 unknown/executing 记录。仅凭调用耗时、已存在成功尝试或取消日志，不能断言下一次请求从未发送；旧记录仍按现有恢复与对账流程处理。数据库写入失败或进程突然退出时，不能把未落盘收尾当作成功，本地回归也不替代真实供应商的账单核对。
