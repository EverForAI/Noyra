# Windows 凭据文件权限

通用文件凭据入口在 Windows 上读取内容前检查实际已打开文件的所有者和
DACL。它适用于 `*_FILE`、`*_CREDENTIAL` 等最终调用 `read_secret_file`
或 `read_secret_bytes` 的入口，包括 operator token、模型/代理凭据、模型组
配置、反滥用密钥、持久 sitemap keyring 和迁移目标 token。钱包口令的
Windows 专用读取路径继续执行自己的钱包存储检查。

## 接受的边界

- 所有者必须是当前有效服务账户、SYSTEM 或 Administrators。
- 适用于该文件的 Allow 项只能授予上述三个身份；即使只向 Everyone、
  Authenticated Users、Users 或其他账户开放读取，也会拒绝。
- 只读服务账户授权可以使用，不强制把凭据改成可写。继承得到的私有 ACL
  也可使用；不要求为了通过检查而删除正常的安全继承。
- Deny 项不授予访问，inherit-only 项不作用于当前文件。无法安全解释的
  对象/回调条件授权、NULL 或无效 DACL、不可获取的所有者/安全描述符均拒绝。
- 仍要求绝对路径、稳定的普通文件、单个硬链接和无 symlink/reparse 路径，
  并执行既有大小、编码和内容检查。

错误返回为对应凭据的 `Windows ACL is unavailable or unsafe`；不包含
凭据正文或完整路径。配置了文件源但文件不安全时，不回退到内联环境变量。
支持文件 ACL 的 Windows 文件系统是必要条件，无法取得 ACL 时不会按
POSIX 模式位或“文件能打开”推定安全。

## 准备与迁移

1. 用实际运行 Noyra 的服务账户确定一处专用凭据目录。创建新目录后，先在
   Windows“属性 → 安全 → 高级”中设置私有权限，再写入任何凭据正文。
2. 所有者使用服务账户、SYSTEM 或 Administrators。若父目录允许 Users、
   Authenticated Users 等宽泛组，先关闭该专用目录的继承，移除这些允许项。
   只保留服务账户、SYSTEM 和 Administrators，并让安全规则传递到新文件。
3. 服务只需读取外部管理的凭据时，可以只授予其读取权限，由受信管理账户
   维护或轮换。不要为了消除错误向 Everyone 加权限，或依赖 `chmod(0600)`
   在 Windows 上建立 DACL。
4. 将已有文件安全迁入后，检查该文件自己的所有者和有效 Allow 项，再配置
   相应绝对 `*_FILE` 路径。原地替换/轮换文件时同样保留这些权限；后续读取
   会重新检查，不沿用旧文件的 ACL 结论。
5. 重启或按该配置入口已有的加载流程验证成功/失败类别。无需输出 token、
   API key、口令、RPC 凭据或配置文件正文。

更新代码不会自动更改用户提供的凭据 ACL、移动文件、删除旧副本或重启服务。
以前因漏检而可读的宽泛 ACL 文件会开始拒绝；升级前应由管理者检查这些
外部文件。应用自己管理的私有目录仍沿用原来的创建和加固流程；新建内部 sitemap keyring
会在临时文件仍为空时建立私有 ACL，再写入密钥并发布。已有 keyring 不安全时
会拒绝读取，不重生成密钥或静默修改它的 ACL。

## 实现与验证边界

检查使用 `GetSecurityInfo` 查询 Python 已打开的文件句柄，而不是重新按
路径探测另一个对象；使用线程有效身份，没有模拟身份时才取进程身份。
每次读取均检查，拒绝发生于 `os.read` 之前；读取路径不生成 PowerShell
子进程、修改 ACL 或缓存权限结果。原有 POSIX 所有者/模式与严格 systemd
只读凭据挂载 ACL 的路径不变。

真实 Windows 测试覆盖宽泛读取、只读/继承授权、NULL DACL、句柄权限变化、
外部文件和命名凭据来源、不安全时不读取字节，以及失败时的资源释放。
该边界不保护已被攻破的服务账户、SYSTEM/Administrator，也不能撤回已被
读取或复制的凭据。它不替代宿主加密卷、凭据轮换和应用运行账户隔离。
