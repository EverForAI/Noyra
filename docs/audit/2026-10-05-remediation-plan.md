### 模块 1：钱包控制

- 已修复暂停/恢复混入未知字段的确定性 400。暂停仅修改暂停标志，开关、模式、限额与收款人策略均保留。
- 控制入口拒绝非 JSON 布尔值和非整数版本，不再强制转换用户意图。
- 策略版本校验、两条必要审计与绑定请求摘要的幂等记录在同一 `BEGIN IMMEDIATE` 事务内；第二条审计失败会回滚全部修改。同 key 同请求可重试，同 key 不同请求返回冲突，并发旧版本只有一个成功。
- 验证：钱包控制、钱包 HTTP/数据、管理台持久会话共 51 项通过；钱包经济规则 7 项通过；修改文件 Ruff 和严格 mypy 通过。
- 限制：紧急暂停阻止后续执行，不能撤销已经广播到链的交易。历史没有请求摘要的幂等记录会保守返回冲突，管理员应使用新 key。

### 模块 2：压缩进度与失败记录

- 压缩在事务内保存按主体/保留天数区分的 keyset 游标和本轮上界；无变化的小记录仍推进游标，有限扫描结束后回扫，覆盖新增旧记录和迟到的终态记录。游标属于可重建维护状态，不纳入主体导出。
- 压缩失败后继续执行派生数据清理，同时写入带阶段、重试时间、失败计数和合法哈希的失败记录。删除事务回滚时同时回退游标与统计。数据库连失败记录也无法写入时，仅输出异常类型日志并返回结构化失败，不记录敏感错误文本。
- 压力恢复通过调用参数与磁盘预检禁用压缩，不再在不足空间时先执行写放大阶段。
- 验证：retention、storage lifecycle、storage pressure 共 45 项通过；model gateway 在前一次组合运行中通过（组合运行唯一失败为随后已修复的测试夹具兼容路径）；修改文件 Ruff、严格 mypy 通过。

### 模块 3：共享解压边界

- 共享 codec 不再允许无限解压，包括显式传入 `None`。默认上限 64 MB，为合法历史模型 I/O 保留兼容空间；训练导出原有更小限额继续生效。
- 所有使用共享 codec 的认知、交互、账本及运行导出读取均受该边界保护。完整性核查通过隔离执行上下文设置更小的单值/剩余总预算，嵌套消费者同样生效；压缩展开字节计入预算，结束或异常后恢复上下文。
- hash 一致但展开 2 MB、审计预算仅 4 KB 的复现返回资源限额，不再返回健康。
- 针对性测试 3 项通过；Ruff、严格 mypy 通过。完整性/导出扩展回归 138 项通过。
