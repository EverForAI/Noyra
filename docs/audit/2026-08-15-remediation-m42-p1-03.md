# M42 P1-03 Archive-Aware Event Integrity Remediation

Date: 2026-08-16

Baseline: `main` / `87e059a` plus the verified M41/M42 remediation work.

## Scope

The audit found that normal cold archival replaces `events.payload_json` with the legal `{}`
tombstone while retaining the original payload hash. `LongRunResilience.audit()` still hashed that
tombstone as if it were the original payload, so every archived event created a false P0 and hid the
difference between a healthy archive, an unavailable key, and real corruption.

P1-03 is split into two independent contracts:

- **A - archive-aware verification:** valid current and legacy segments reconcile their database
  manifest, tombstones, timestamps, encrypted object, restored payloads, and retained event hashes
  under one consistent and bounded snapshot.
- **B - severity classification:** unavailable or ambiguous verification evidence reports degraded
  P1, while corruption that can be proven from database, key, object, or payload evidence reports
  corrupt P0 without changing the SQLite result.

This remediation does not wire the verifier into production startup or periodic scheduling and does
not implement a versioned archive keyring, rotation, cloud read-through, or restore. Those remain the
separate P1-02 and P1-11 contracts.

## Implemented boundary

`src/noyra/core/event_archive.py` now performs database-only manifest preflight before opening the
archive key. It verifies segment/object-key identity, exact integer event counts, format/key metadata,
first/last event time, segment creation time, event `payload_archived_at`, tombstones, missing segment
references, and complete segment/event reconciliation. Legacy segments with all three optional
format/key fields unset remain readable with the original external key, preserving the M3 contract.

The payload phase then verifies bounded local reads, AES-GCM authentication, compressed hashes,
bounded zlib decompression, archive body format/subject, duplicate or unexpected IDs, inner payload
hashes, and the retained database payload hash. Local reads use `limit + encryption overhead + 1`
rather than a stat/read race. Segment metadata and event rows are cursor-iterated; only one segment
and at most 5,001 row references can be materialized at a time. The additive
`idx_events_subject_archive_time` index serves the subject/archive/time reconciliation path.

The synchronous verifier has explicit defaults:

- 64,000,000 decompressed bytes per segment;
- 512,000,000 decompressed bytes per run;
- 2,048 segments and 100,000 events per run;
- the archive format's fixed maximum of 5,000 events per segment; and
- 2,000,000 bytes per hot event payload and 128,000,000 total hot payload bytes.

`LongRunResilience` holds one SQLite `read_transaction()` across the database checks, so a concurrent
archive commit is observed as either the complete old state or the complete new state. Resource-limit
exceptions, key absence, and provider I/O are handled inside the event archive check and preserve the
successful SQLite result and real event count. The outer audit fallback also no longer rewrites a
successful SQLite check when a later non-database component raises.

Classification is deliberately evidence-based:

- missing/wrong keys and legacy authentication ambiguity: `degraded:key_unavailable`;
- temporary provider I/O failure: `degraded:unavailable`;
- hot/archive byte, segment, or event verification budget exhaustion:
  `degraded:verification_limit`;
- proven manifest, count/type, timestamp, tombstone, object, authentication, body, ID, canonical JSON,
  or payload-hash corruption: `failed` plus `event_archive:corrupt` P0.

If both fingerprint evidence and ciphertext are changed, or unauthenticated bytes exceed the read
envelope, the current single-key format cannot prove whether the operator supplied the wrong key or
the object was altered. Those cases remain conservative degraded states. P1-11 key history is needed
for a stronger conclusion.

## Evidence

The focused contract file is `tests/test_m42_p1_03_archive_integrity.py` (35 tests). It covers:

- valid current and legacy segments, multiple segments with identical timestamps, restored payloads,
  and unchanged event-chain roots;
- one-snapshot behavior while a second connection commits a new archive segment;
- missing/wrong keys, provider unavailability, bounded reads, decompression limits, hot-payload
  limits, and valid segments above a caller's synchronous event budget;
- ciphertext, compressed/object, body format, key ID/fingerprint, count type/value, time range,
  creation time, segment ID, missing object/metadata, duplicate event, inner payload, tombstone, NaN,
  and recursive JSON corruption; and
- precedence of database corruption over missing keys plus the documented conservative ambiguity
  cases.
