# M42 P2-03 Bounded HTTP Response Remediation

Date: 2026-08-15

## Scope

This remediation closes the response-buffering and missing-response-limit finding for configured
search APIs, browser search, and the HTTP messaging transports named by the read-only audit. It does
not claim to close SMTP delivery semantics, model or embedding endpoint pinning, or the remaining
cross-resource usage-ledger and circuit contracts.

## Changes

- `noyra.core.http` provides a shared bounded streaming reader. It rejects response header fields
  above 64 KB, invalid or oversized declared lengths, non-identity content encoding, and bodies above
  2 MB before appending an oversized chunk to the result buffer.
- Search and browser adapters now keep responses inside `AsyncClient.stream()` contexts, apply one
  total deadline across response-header acquisition and body streaming, disable redirects per
  request, and always release the response context on success, failure, timeout, or cancellation.
- HTTP messaging delivery uses the same header and body limits with a 20-second total deadline.
  Response-limit and response-timeout failures after a side-effecting request are quarantined as
  `unknown` and are not automatically retried, preserving the existing duplicate-delivery boundary.
- All affected requests ask for `Accept-Encoding: identity`; an upstream that ignores that request
  and sends compressed content is rejected before HTTPX can expand the response body.

## Evidence

- `tests/test_m42_p2_03_http_bounds.py` covers exact and crossing body limits, declared length,
  header size, encoded bodies, slow body streams, delayed response headers, per-request redirect
  suppression, response-context release, and the search/browser/transport adapter matrix.
- The transport test proves an oversized response becomes `unknown`, releases the stream, and does
  not trigger a second delivery attempt.
- Focused P2-03 tests: `8 passed`; P2-03 plus existing research and transport regressions:
  `31 passed`.
- M41 targeted smoke and large profiles: `61 passed` each; full repository pytest: `334 passed`.
- Deployment audit: `40 passed`, `72.07%` coverage. Ruff, format, Mypy, compileall, pip check, and
  production-lock `pip-audit` passed.

## Residual risk and follow-up

The HTTP library still performs its protocol-level parsing before the application can inspect the
logical response header fields; HTTPX/httpcore's protocol parser remains the first header-line
defense, while this contract adds the explicit application cap. P2-04 and P2-05 remain responsible
for SMTP pinning and provider-specific unknown-delivery reconciliation. P2-07 remains responsible
for model and embedding endpoint network boundaries. Windows gates ran locally; the reproducible
Ubuntu entry could not run because this machine has no installed Ubuntu/WSL distribution.
