每模块增加根因回归，验证正常/失败/历史/状态变化路径，复审改动与消费者，再独立提交并进入下一模块。最后运行跨模块集成、全量静态检查、前端检查；按实际结果记录平台限制。

- 本次仅本地修改与提交；不推送、不合并、不部署服务器。
- 不删除 unknown 调用、尝试、不确定费用和审计；不自动更换请求身份、transport、binding 或会话。
- 不按昵称推断归属，不删除私人目标或记忆；不放开未知审计事件，不降低完整性策略。
- Windows 验证用临时包、内存测试证书和系统签名测试 launcher；不启动 EXE，不修改证书库，不从包自述信息建立信任。
- O01/O02 为语义观察，不擅自改成新全局门禁。Windows 严格安装后的恢复需求由外部受控策略保存，旧策略兼容与撤信必须明确。
- 不重装或升级本地依赖掩盖环境差异；所有验证记录实际解释器与跳过原因。

## 实施记录

### 模块 1：D01（完成）

- 两个参与者新写入器改用 canonical_json；仅为这两种明确事件兼容历史 json.dumps 默认格式，没有放开任意 JSON 或未知事件。
- QQ 关联/解除关联审计校验精确字段、operator、同主体 binding 和布尔同意；不以当前 enabled/consent 状态否认合法历史。
- 申请撤回补充引用消息的方向与参与者归属检查，不能仅凭同一 key 证明归属。
- 新增 17 项回归涵盖真实 HTTP、真实撤回（已决定/未决定）、旧格式、新格式、状态撤销、QQ 同意变更、完整性和 pause 策略；篡改 actor/字段/跨主体/重复 JSON/NaN 仍拒绝。
- 验证：新增回归 17 passed；真实消费者组合 37 passed、129 deselected；所改文件 Ruff/格式/Mypy 通过。两组有交叠，不叠加为独立用例总数。
- 复审：兼容不重写旧事件，不改变主体行为或 schema；成功与篡改路径实际经过 core.actions。未发现该模块阻断项。


### 模块 2：D05（完成）

- 社交生成不再读取全局活动目标；自生、环境与混合来源不能作为向特定收件人披露的授权。保留原有私人目标存储、状态和内部认知能力。
- 社交证据仅传递 event_id、类型和时间，不传递可包含私人内容的全局 source 或内容指纹；仍执行证据引用与冻结路由校验。
- 三种目标来源回归实际构造 Bob 私聊、内生目标及含秘密的事件 source，以仅回显实际输入的提供商运行完整社交流程；Alice 输入和输出均不包含秘密，Bob 目标仍完整存在。
- 验证：社交相关组合 30 passed、21 deselected；所改文件 Ruff/格式/Mypy 通过。复审成功调用复用、证据集合、目标持久化与消息路由后，未发现模块阻断项。

### 模块 3：D06（完成）

- 优先级头页与 keyset 续页各最多 32 条；按熟悉度、亲近度、更新时间和唯一 ID 稳定排序。整页无可用对象时保存主体专属续页游标，重启可继续；到尾自动复位。
- 每次仍检查优先级头页，使恢复授权的高优先级联系人及时可见。单次最多检查 64 个关系，输出仍只包含一个已验证收件人。
- 消息限额在同一参与者身份（或没有身份关联的确切旧 counterparty）内应用，不再先截全局最近 48 条。没有按昵称、前缀或相似名称猜测身份。
- 新回归覆盖 12/80 个不可路由关系、50 条无关新消息、跨实例恢复续页、页尾复位、路由撤回/恢复与旧联系人。33 passed、21 deselected；所改文件 Ruff/格式/Mypy 通过。
- 复审冻结来源、binding/transport 校验、模型 unknown/重试围栏和提交前撤销检查，均保留。无需 schema 迁移；游标不记录消息内容。查询返回量有界，极大历史库的 SQL 耗时仍需按实机负载评估，不宣称固定时间上限。未发现模块阻断项。

### 模块 4：D02—D04（完成）

- D02：先规范化省略/null/空/单/多指纹再判断回读，恢复外部策略默认复用；不接受包自行授予信任。
- D03：每个版本验证完成后，在安装根目录原子保存 signature_required 记录，再发布 current。回滚独立读取当前版本的记录，完整验证 previous，不需要损坏 current 先通过验证。暂存二次校验保留首次验证的严格要求并核对版本，不能在复制过程中降级。
