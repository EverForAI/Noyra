# M42 P1-07 Training Export Resource-Bound Remediation

Date: 2026-08-16

Baseline: `main` / `87e059a` plus the verified M41/M42 remediation work.

## Scope

The audit found that training export retained an unbounded in-memory deduplication set and
episode list, could serialize a multi-year episode in one operation, and used the host system
temporary directory. The old path also had no enforced work/archive/free-space budget, no shard
manifest, and no bounded compatibility byte API. A long history could therefore exhaust RAM,
the Windows system volume, or a small container `/tmp` before the final ZIP size was checked.

P1-07 is split into two independent contracts:

- **A - bounded data path:** deduplication, episode assembly, payload decoding, JSONL records,
  sharding, ZIP output, and compatibility results remain within explicit row and byte limits.
- **B - bounded storage lifecycle:** owned temporary and pending files use the managed data
  volume and are cleaned on success, cancellation, failure, disk-full, and restart recovery.

This remediation does not claim to close P1-09/P1-10/P1-11 or any other unrelated long-term
retrieval, embedding, archive-key, or cloud-storage finding.

## Implemented boundary

`src/noyra/core/training_export.py` now exposes one `TrainingExportLimits` contract for work,
archive, compatibility, subject-quota, free-space, record, episode, shard, workspace, and legacy
row limits. The streaming exporter:

- uses `data_root/exports/work` by default, requires any custom work root to remain inside the
  managed `data_root/exports` tree, and rejects final targets outside that tree;
- uses an exact SQLite fingerprint table with a fixed page cache, `temp_store=MEMORY`, disabled
  mmap, a page-count cap, and actual file high-water accounting instead of an in-memory `set`;
- flushes episodes on event count, elapsed span, or serialized episode-byte thresholds, and
  writes bounded JSONL records to shards with per-shard row, byte, and SHA-256 manifest entries;
- rejects over-sized stored event payloads before JSON materialization, bounds zlib/model and cold
  archive decompression, and reserves ZIP central-directory overhead while chunks are written;
- accounts work files, the deduplication database, the staged archive, SQLite snapshot images,
  subject quota, and free-space headroom while the operation is running;
- installs SQLite progress handlers during query execution and uses progress checkpoints during
  snapshot backup, row streaming, workspace reads, hashing, ZIP writes, and publication; and
- bounds the legacy builder by both rows and canonical JSON input bytes. The compatibility
  `export()` API caps the archive before publication and never reads an over-sized ZIP into RAM.

`src/noyra/core/payload_codec.py`, `event_archive.py`, and `archive.py` enforce bounded reads and
decompression for model, event, and cold-segment payloads. `StorageUsageScanner` includes the
managed exports tree and active/orphaned SQLite snapshot images in quota accounting.

Cleanup is fail-closed. Writer and dedup handles close on every exit; normal success,
cancellation, exception, and ENOSPC paths remove their partial JSONL, dedup, snapshot, pending ZIP,
and work files. Ownership-gated restart cleanup immediately removes only the exporter's owned work
and pending archive names. Snapshot images use the separate P2-16 lock-aware stale scavenger after
its grace period on a subsequent snapshot operation. The existing P1-05 consent publication and
P1-06 cancellation decision boundaries remain in force.

## Evidence

The focused contract file is `tests/test_m42_p1_07_training_bounds.py` (24 tests). It covers:

- data-volume work roots, disk-backed deduplication, bounded episodes, JSONL sharding, and
  manifest hashes;
- query plans without unmanaged temporary sorts and progress-handler cancellation;
- work, archive, quota, and free-space exhaustion;
- stored, compressed-model, and cold-archive payload limits;
- cancellation, partial writes, writer-open failure, and restart scavenging; and
- compatibility-byte and legacy builder limits.
