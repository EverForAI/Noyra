## 5. 外部验收门禁逐项记录

### EXT-01：Ubuntu/systemd 安装、升级与恢复

- **风险等级：P1 发布阻断。** 未能证明安装器与 systemd 在目标发行版、真实权限和最终 SHA 下能完成启动、升级、重启及失败恢复。
- **修复风险：中至高（操作）。** 需要 staging 主机和可恢复快照；操作错误可能影响服务可用性或升级前状态。代码修复尚无证据表明必要。
- **根因：** 最终 SHA 的 pending 验收记录没有部署执行人、独立复核人、时间和日志引用。Windows/WSL 脚本测试不能覆盖真实 systemd 依赖、用户/组、unit 顺序和重启行为。
- **影响：** 首装、版本升级、schema 变更后的启动、服务账户权限及自动回滚是否符合预期仍未在目标 OS 证明。
- **触发条件：** 首次真实安装；升级到 schema 80；电源/进程重启；注入安装中断或健康检查失败。
- **触发概率：** “缺少证据”当前确定为 100%；安装失败概率未知，需在真实平台测量。
- **建议：** 生产部署前立即验收；隔离 staging 可以先暂缓。执行完整新装、升级、重启及故障回滚，记录安装日志、服务状态、ready 状态、版本 SHA、schema 和备份恢复结果。

### EXT-02：真实 LUKS 加密卷与失败关闭

- **风险等级：P1 发布阻断。** at-rest 设计可能正确，但真实数据卷解锁、挂载识别、权限及重启后的拒绝行为没有真机证明。
- **修复风险：高（操作）。** 加密卷格式或 key 管理操作错误可能造成不可恢复的数据丢失；仅在一次性验收主机和已验证备份上执行。
- **根因：** 自动化测试中的加密设备探测仍由 fixture/模拟状态驱动。POSIX 权限测试虽使用独立非 root UID，但它不证明真实 LUKS 设备和密钥生命周期。
- **影响：** 无法确认数据未挂载、错设备、密钥不可用、权限放宽或重启时服务是否 fail-closed，也无法证明已挂载的数据确实位于加密介质。
- **触发条件：** 新装、服务器重启、卷未挂载、密钥缺失/错配、卷标或 mapper 变化、目录权限错误。
- **触发概率：** 当前缺少实测证据是确定状态；真实误挂载或解锁故障概率未知。
- **建议：** 要求 at-rest 的生产环境立即验收。使用可销毁主机验证正常解锁和各拒绝场景，并在恢复备份可用后再测试；未完成时不能把 at-rest 标记为真机验收通过。

### EXT-03：认证备份和干净主机恢复

- **风险等级：P1 发布阻断。** 备份成功写出不能证明数据库、冷归档、工作区和密钥引用在另一台干净主机可完整恢复。
- **修复风险：高（操作）。** 错误密钥、密钥轮换和生产备份误覆盖都可能造成数据不可恢复；应使用副本、隔离目录和恢复演练。
- **根因：** 当前 pending 证据没有从真实来源卷创建、在干净主机恢复并核对对象的记录。Windows/本地测试只覆盖代码和测试存储行为。
- **影响：** 生产数据灾难恢复、归档历史读取和迁移前置备份的可用性没有外部证明。
- **触发条件：** 机器丢失、数据卷损坏、迁移前恢复、密钥错误/轮换、归档对象缺失或摘要篡改。
- **触发概率：** 验收缺失确定；灾难发生频率与恢复失败概率均未知。
- **建议：** 有任何重要生产数据前立即验收。真实生成认证备份，在无旧数据的新主机恢复，逐项检查 schema、主体身份、冷对象可读性、工作区内容及摘要；另用错钥和篡改包验证拒绝。

### EXT-04：双机迁移与单活保证

- **风险等级：P1 最高优先级发布阻断。** 双端同时获准写入会破坏主体连续性，并可能重复发送消息或付款。最新代码已有严格请求/回执、fence 和可靠回滚实现，但真机组合尚未证明。
- **修复风险：很高（操作）。** 故障注入涉及双机停用、数据库切换和身份恢复；在生产数据/生产钱包上测试有不可逆风险。代码修复风险暂未重新确认。
- **根因：** 需要两台真实 Ubuntu 主机及真实网络中断、systemd 和 LUKS；pending 记录没有对应证据。桌面端测试只能验证状态机和模拟外部行为。
- **影响：** 当前不能据此解除迁移默认关闭，不能证明目标已激活但回执丢失时来源持续隔离，也不能证明持久停用、迟到激活、重启恢复和本地钱包材料的真实合同。
- **触发条件：** 正常切换、传输中断、远端激活回复丢失、目标不可达、来源重启、回滚中断、双端同时启动或收到迟到激活。
- **触发概率：** 缺少真机证据确定；网络/进程故障的真实频率未知。若触发了不可靠环境边界，后果可能严重。
- **建议：** 在任何迁移功能启用前立即验收。两台一次性主机、测试主体和测试钱包；按最终验收矩阵逐个故障注入。断言始终最多一个端点可写，目标无法确认持久停用时来源必须保持隔离。真实单活证据缺失期间保持迁移关闭。

### EXT-05：外部 signer/KMS 绑定证明

- **风险等级：P1（适用于选择外部 signer 的迁移路径）。** 代码中的 EIP-191 任务/目标挑战未被真实 signer/KMS 产品、凭据分配和轮换场景验收；无效绑定可能使迁移后钱包与预期签名身份不一致。
- **修复风险：高（操作）。** KMS 访问策略、签名挑战、密钥轮换配置有误会造成钱包不可用或错误身份；验收请求不得转化为链上交易。
- **根因：** 没有最终 SHA 的独立 signer/KMS 执行和独立复核签名证据。模拟 signer 的正确签名无法证明部署服务的 IAM、网络或密钥 alias 行为。
- **影响：** 若用户选择 `external_signer_rebind`，目标端 signer 访问控制、身份连续性、拒绝错误地址/任务及轮换回退尚无实证。
- **触发条件：** signer/KMS 初次绑定、目标切换、访问被拒、凭据过期、密钥轮换、错误 signer ID 或挑战重放。
- **触发概率：** 未验收事实确定；实际配置失败概率未知。若未使用外部 signer，此特定路径不触发，但不能用本地钱包测试替代外部 signer 选项验收。
- **建议：** 启用外部 signer 迁移前立即验收；暂不支持该部署选项可暂缓此子项，但须在管理台/部署策略中保持该模式不可用。逐项测试错地址、错任务、过期挑战、拒绝凭据和密钥轮换；身份挑战不能提交付款。

### EXT-06：链上 nonce、未知广播和重组

- **风险等级：P1（自动付款开放前阻断）。** 自动付款可涉及实际资产。钱包逻辑和本地测试覆盖限额、暂停与状态恢复，但真实链确认深度、RPC 不同响应、nonce 竞争和重组语义尚未验收。
- **修复风险：高（操作/资金）。** 即便使用测试链，广播未知、nonce 已消耗与重组验证操作复杂；使用主网或有价值资金不适合作验收。
- **根因：** 当前八项外部门禁无真实测试链收据或复核证据；本地 fake RPC 无法证明节点、provider 和链的实际行为一致。
- **影响：** 未证明未知广播不会自动重复付款，也未证明长时间 pending、nonce 冲突、链重组和终局状态能正确进入明确状态并受暂停/限额约束。
- **触发条件：** 两个执行者并发取 nonce；发送方已接受交易但 RPC 回复丢失；长时间未确认；交易被替换或纳入后重组。
- **触发概率：** 证据缺失确定；实际链上事件概率取决于链、节点和负载，当前无样本可量化。
- **建议：** 启用任何自动付款前立即验收。只用可控测试链/测试资产，小额逐条构造场景并核对执行台账和 on-chain nonce；证明 `unknown` 不会自动重付，紧急暂停和日额/单笔上限在每个重试入口生效。
