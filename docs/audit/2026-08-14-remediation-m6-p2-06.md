# Noyra P2-06 修复复核

日期：2026-08-14  
范围：撤销资源后 secret 文件删除失败没有持久化修复路径。

## 修复内容

新增 `secret_cleanup_queue`，只记录 subject、资源类型/ID、受限的相对 secret 引用和
错误元数据，不记录密钥内容或绝对路径。模型、搜索和通讯资源撤销成功后，文件删除
失败会进入 `pending/failed` 队列；各 secret store 初始化时按资源目录执行有限重试，
成功后标记 `removed`，失败则指数退避。

数据库状态不会因为一次磁盘权限或临时占用错误回滚；资源已经 revoked，运行时也不会
再读取其 secret。引用路径必须解析到对应 secret 目录的直接子文件，越界引用会继续失败
并留在队列中。

## 验证

* 新增队列删除与状态回归测试；
* 三类资源 store 的撤销/替换路径接入队列；
* 全量测试、静态检查、依赖审计和 Ubuntu/部署专项审计在提交前执行。
