# M42 P2-01 Training Workspace Scope Remediation

Date: 2026-08-15

## Scope

This remediation closes the training-export workspace ownership finding. It changes only the
workspace input boundary and export manifest; event, memory, and model-data eligibility remains
controlled by the existing training policy.

## Changes

- Training workspace discovery starts at `workspace/<subject_id>` and rejects a shared-root,
  blank, path-separated, escaping, or link/reparse-point subject key.
- The manifest records the logical subject, selected storage key, source root policy, archive root,
  no-follow policy, reparse-point policy, and rename identity recheck.
- Workspace traversal prunes blocked directories and link/reparse points. POSIX reads use directory
  file descriptors with `O_NOFOLLOW`; Windows reads use no-follow-compatible flags where available,
  descriptor identity checks, and post-read containment checks.
- A file is included only when its descriptor identity matches the pre-read path identity and the
  subject root remains unchanged. A rename/replacement race therefore fails closed rather than
  packaging bytes from another subject.

## Evidence

- Two-subject export test includes only the selected subject's file and excludes shared-root and
  sibling-subject files.
- Manifest test asserts the exact `workspace_path_policy` and selected storage key.
- Foreign directory link and Windows junction/symlink tests never include the linked subject's
  bytes; an invalid subject-root link fails closed.
- Deterministic rename race swaps a selected file with another subject's bytes during the read;
  descriptor identity validation excludes the substituted content.
- P2-01 focused tests: `4 passed`; P2-01 plus storage regression tests: `16 passed`.
- Final deployment audit: `40 passed`, `72.07%` focused coverage.

## Residual risk and follow-up

The export boundary now has explicit subject ownership, but multi-file prototype publication still
has a separate staging/atomic-commit contract under P2-13. Subject identifiers are restricted to a
single workspace path component here; the broader stable ASCII ingress and independent storage-key
contract remains tracked under P2-18. The Windows contracts ran locally; no Ubuntu distribution is
installed in this workspace, so the POSIX runner remains a required CI follow-up.
