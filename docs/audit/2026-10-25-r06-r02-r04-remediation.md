## 模块一：R06（P3，修复风险低）

边界：仅调整测试输出捕获和诊断，不修改产品逻辑、警告设置或文件系统隔离。

修复：`mklink /J` 输出按 bytes 捕获；失败时以 UTF-8 + backslashreplace 生成诊断，非 UTF-8 字节可追溯且不触发读线程解码异常。新增两个确定性反例检查捕获模式和错误字节保留。

验证：原始六项在本次环境已通过（当前控制台编码未再现历史告警，不能据此否认审计）。仅加入新测试时得到 1 failed / 1 passed，失败明确指出原实现仍传 `text=True`。修复后在 `PYTHONUTF8=1`、`PytestUnhandledThreadExceptionWarning` 视为错误下 8 passed；Ruff 与格式检查通过。

差异审计：仅测试夹具和新增测试变化；真实跨主体内容排除、根链接拒绝及 rename-race 断言未删除；无产品代码、警告过滤或依赖变化。

## 模块三：R04（P2，修复风险中）

目标：迁移所有主体 ID 入口共享运行时的安全合同，合法自定义和 127/128 字符 ID 可通过。

边界：保留设备名/危险字符拒绝、路径隔离、签名/MAC/摘要及主体绑定，不改写既有 ID，不生成替代身份。


修复：Agent enroll、binding proof、接收/恢复 manifest、bundle 认证上下文/manifest、激活合同及恢复备份登记使用 core.identity 的同一主体 ID 验证器。保持原始字符串，不加前缀、不改大小写、不改写 ID；未改变请求/回执格式、签名字节算法或持久 schema。

实施中补充确认同一根因的另一处副本：ServiceSettings 的 Field 原为最短 8 字符，即使其字段验证器调用 core 的 3–128 字符合同，3–7 字符值仍会被提前拒绝。现将这一声明同步为 3–128。原审计对 ServiceSettings 全区间一致的表述在此更正；这不是本次修复新引入的问题。

特权 runner 原本对 subject_id 使用允许点号/冒号的通用任务 ID 合同。为避免给原来可独立执行的 SQLite 恢复路径引入应用包或第三方依赖，保留 stdlib-only 边界，在脚本内镜像安全主体合同；以核心验证器为预期执行合法/非法值一致性矩阵，并以 Python -I -S 验证独立加载不会导入 noyra。任务、epoch 等其他 ID 保留各自合同，未一并放宽或缩窄。

定向验证：修正认证夹具后，在未修复产品上 6 个合法值的贯通测试得到 4 failed / 2 passed；失败分别定位 3 字符服务配置、自定义 ID、127/128 字符 enrollment；默认 ID 与 126 字符控制组通过。修复后的专项矩阵 135 passed，涵盖运行设置/身份存储、真实收件人加密、Agent 恢复、签名绑定证明、激活请求及回执、非法字符、长度边界、保留设备名和无 I/O 的早期拒绝。证明/回执换绑至其他合法主体仍被拒绝，篡改签名字节后验证失败。

差异审计：不触碰主服务所有权、运行锁、费用账本、关系信任、Windows signer 轮换协议或包签名策略。共享验证器只对主体 ID 生效；激活合同仍检查所有其他 identity/digest/wallet 字段。已有主体不需要数据迁移；旧包/历史证据不被重签或重新散列。无新增依赖及生产操作。

## 额外发现：Windows 长路径限制（范围外，基线可复现）

- 问题风险：P2；修复风险：中；归因：既有问题（未修复的 ac17c5d 基线同样复现），不是本次三个模块造成的次生问题。
- 位置：core/integrity.py 的 _atomic_json，摘要文件 os.replace；scripts/audit-m41.py 将临时树置于工作树内会在深层 Windows 工作树放大该条件。
- 根因/触发：本机 LongPathsEnabled=0；深层数据根导致 integrity-run_*.json.sha256 目标长度为 261 字符。报告 JSON 能写出，但摘要发布抛 WinError 3，服务 boot 被中断。不是完整性发现了主体损坏，也不是迁移/签名合同改变。
- 证据：修复分支在与原 smoke 完全同深度的独立临时目录中失败；切回 ac17c5d 原工作区、保持等长临时根重复该单测，出现同一 _atomic_json / os.replace 错误；修复分支使用较短临时目录的同一单测通过。
- 影响：受限 Windows 环境下，足够深的数据根可能导致服务启动失败。未证明 Linux 或常规短数据根受到同一 Windows 路径限制影响。
- 本次处理：停止已经确认受此条件影响的长路径 smoke 运行，不把它记录成通过；仅在运行器内将 TEMP_ROOT 指向仓库外较短临时根，重跑同一脚本、同一 targeted/smoke 测试集合与断言。未修改门禁、注册表或产品代码以掩盖失败。本项不在用户授权的 R06/R02/R04 中，保留待后续单独设计路径合同修复。
