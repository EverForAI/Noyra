# M42 P1-01 Sleep Deadlock Remediation

Baseline: `main` / `87e059a` plus M41 verification infrastructure.

## Contract

The autonomy loop must not report `sleep_requested` unless a sleep run was created. A prepared
action is recoverable work, not an automatic failure: the active workflow gets a chance to settle it.
If it remains unsettled past the configured deadline, the runtime enters durable `paused` state and
waits for an explicit action disposition. Restarting resets neither the prepared action nor the
truthful blocked result.

## Change

`AutonomyLoop` now catches a sleep/action conflict as an explicit state rather than suppressing it.
It records a private `autonomy_sleep_blocked` event, invokes the active hook, retries sleep after the
hook, and reports `sleep_blocked` while the action remains unresolved. The new
`sleep_conflict_deadline_seconds` setting defaults to five minutes. At the deadline the kernel
pauses; it never silently marks a prepared action failed. A hook that settles the action can create
the sleep run in the same tick.

The conflict start is recorded as an append-only event, so a restart reuses the original blocked
event rather than resetting the bounded deadline and still returns `sleep_blocked` or enters
`paused`; the prepared action remains durable. No schema migration or new action status was
introduced.

## Evidence

- `tests/test_m42_p1_01_sleep_deadlock.py`: settlement, deadline-to-pause, and restart regressions;
- full pytest: 326 passed;
- Ruff, format check, Mypy, compileall, pip check, and pip-audit: passed;
- deployment audit: 40 passed, 72.07% focused coverage;
- no production P0/P1 finding was introduced by this change.

P1-01 is `verified` in the M41 acceptance matrix. P1-08 and P1-13 remain separate Gate A contracts.
