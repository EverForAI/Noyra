## A01：匿名冷归档读取仍有文件系统副作用（P1）

根因：src/noyra/interaction/public_archive.py 的生命周期读取构造 EventPayloadArchive 时传入 create_root=False，但 src/noyra/core/event_archive.py 仍进入归档根解析。src/noyra/core/archive.py 的 resolve_subject_archive_root 使用 SubjectStorageDirectory.locate；其旧目录分支仍可执行 os.replace(legacy,target)。create_root=False 只阻止创建，不阻止旧路径迁移。

影响：访客 GET 可能重命名主体归档目录，改变归档任务依赖的物理路径，并与同时运行的归档/清理任务形成竞态。隔离复现得到 directory_layout_changed=true、legacy_exists=false、keyed_exists=true，证明这是实际文件系统行为。迁移前构造且仍指向旧路径的 LocalArchiveProvider，迁移后 get 抛 FileNotFoundError；不能据此宣称生产任务已失败，但旧路径引用失效已复现。新路径下正文仍可读，没有观察到文件内容被删除。

触发条件与概率：旧主体目录布局仍存在，且公开生命周期记录指向本地冷段；满足条件的首次匿名冷读近似必现。新布局或热事件不触发。

修复风险与安全边界：中风险。读取路径必须只解析现有目录，禁止 os.replace、mkdir、迁移和云恢复写入；写入/升级流程仍可在明确拥有者上下文迁移旧目录。必须保留多主体绑定、符号链接拒绝和密钥/hash 验证。

建议：立即修复，增加旧布局冷读前后目录树完全相同、多主体、符号链接和并发测试。修复前不能把公开冷生命周期 GET 称为严格只读。

## A02：超过两个冷段的公开列表会错误降级（P2）

根因：_LifecycleReader.states 将一次分页可解密段数硬限制为 2。限制有安全目的，但 _page 要先验证 limit+1 候选，且 all 查询对每个类别分别读取再合并，没有段游标、段索引或热/冷混合继续路径。因此未最终显示的 lookahead 或生命周期候选也可能耗尽段预算，最后不给继续游标。

影响：长期主体有三个以上冷段时，默认生命周期列表、总览相关读取和 sitemap 返回 503 public_query_budget_exceeded。隔离数据生成三个段后，limit=1 可读第一条，但默认页直接得到 PublicQueryBudgetExceeded；HTTP 返回 503。数据并未损坏，这是容量合同过窄。

触发条件与概率：一次分页需验证的候选跨越三个不同 payload_archive_key 时必现；不是数据库只要存在三个段就所有页面都会失败。短历史概率低，持续运行、频繁归档或全量 sitemap 后概率随访问历史跨度增长。同一隔离库的单 ID 独立 HTML 仍为 200/no-store。

修复风险与安全边界：直接放大段数会增加解密、内存和时延，风险中高。必须保留总字节、事件、SQL 和墙钟预算；不能删除 local-only、hash、主体绑定或改成伪造空页。

建议：立即设计分段游标或只读索引，游标绑定主体、过滤器和段位置；sitemap 使用分区或异步已验证索引。

## A03：撤回当前编辑项后仍显示旧 revision（P2）

根因：src/noyra/web/admin.js 的 withdrawPublicPublication 完成撤回后只刷新列表，没有检查 publicationEditor.id 是否为被撤回 ID，也没有清空或标记编辑器；publicationFields 仍允许用旧 revision 组织保存。

影响：编辑器可继续显示修订 1，列表已是 withdrawn/revision 2。后续保存得到 409，草稿进入待核对状态；服务端 CAS 保护了数据，但界面会造成撤回失败错觉和重复操作。

触发条件与概率：当前摘要被当前窗口或另一窗口撤回后不重新打开编辑器；满足条件必现。

修复风险与安全边界：低中风险。当前项撤回后应标记草稿的基准修订已失效，提供保留草稿并重新打开最新副本的路径；不能无提示清空未保存文字。撤回另一项必须保留当前草稿。不能删除原始记录、绕过 CAS 或自动重新发布。

建议：立即修复并验收慢请求、409、401、当前项和另一项撤回。

## A04：不明结果对账误判规范化等价内容（P2）

根因：admin.js 的 reconcilePublicPublication 只排序结构 JSON，没有使用服务端 _text/_timestamp 规范化。服务端会 trim 文本、把 Z 转为 +00:00，待发送 payload 仍可能保留空格或 Z。

影响：网络超时后服务器已成功发布，管理台查到同一语义摘要，却显示内容不同而不采纳；管理员可能反复修改或新建。CAS 降低了重复写入风险，但成功结果会长期处于不明状态。

隔离证据：合成对账中 active 与前后空格状态被判不同；带 Z 与带 offset 的同一时间也被判不同。现有 Node 106 项未覆盖这两个边界。

触发条件与概率：先发生网络不明结果，再提交可规范化状态或时间；满足条件必现。

修复风险与安全边界：中风险。客户端应复用服务端同源 canonicalization，仅比较允许字段；未知字段、数组和他人真实差异必须仍冲突，不能相似即采纳。

建议：立即修复。首次发布前规范化并冻结同一 payload，保留不明结果的同 ID 重试；对于已有不明 payload，按服务端同源规范化比较。补 trim、Z/offset/毫秒、数组顺序和他人修订矩阵测试。现有 409 也会进入不明结果状态，是明确拒绝与待确认结果划分不充分；不能在曾经超时后收到 409 就推定之前从未成功。

## A05：DST 回拨小时编辑会静默改变时间（P2）

根因：admin.js 用无 offset 的 datetime-local 回填，并通过 new Date(value) 与当前时区偏移换算。回拨重复小时有两个合法瞬间，浏览器会选择一个默认解释。

影响：只改标题时，旧时间也可能被重新提交。隔离时区复现：2026-11-01T06:30:00.123Z 显示为 01:30，再次收集变为 2026-11-01T05:30:00.123Z，相差一小时。公开预测和睡眠时间线因此被静默改变。

触发条件与概率：回拨重复小时的旧摘要被打开并保存；满足条件必现。窗口每年短且仅部分时区，无条件概率低，但影响确定。

修复风险与安全边界：中高风险。保留带 offset 原值；可使用带时区编辑、保存仅在明确修改时转换，或在歧义时要求选择 offset。不能仅改 step 或测试时区。

建议：立即修复，加入 DST 回拨/前进、UTC、无 DST 的 round-trip 测试。

## A06：独立阅读页破坏投稿草稿和列表上下文（P2）

根因：app.js 将卡片链接改为完整 /public/{kind}/{id} 文档导航。投稿草稿只在当前 SPA 内存，离开前没有保存；独立页返回链接 /#view 也不含筛选器、cursor 或批次。

影响：填写投稿后用 hash 导航到日记列表，草稿仍在；随后点击阅读全文，再用独立页的“返回公开档案”链接返回并进入投稿页，标题和正文为空。隔离 Playwright 实际得到 title=""、body=""。这条操作不需要用户手动刷新/关闭浏览器。独立页返回链接也未携带原筛选和批次。浏览器后退是否从 bfcache 恢复受实现影响，本次不宣称所有后退都丢草稿。

触发条件与概率：未提交草稿点击卡片/阅读全文，再用页面返回链接重新加载 SPA；本次 Chromium 路径必现。仅 hash 切页仍保留草稿。

修复风险与安全边界：低中风险。可用新标签、sessionStorage 仅本地保存草稿，或恢复原 URL 状态；不得把草稿发到服务器、模型或共享账户。

建议：立即修复，或在离开前明确提示并取得放弃草稿确认；只更新一句文案不足以恢复既有草稿保留目标。可优先将站内普通点击保留为 hash 阅读，而复制/新标签/爬虫仍使用独立 canonical 路径。若采用 sessionStorage，应设字节上限、成功后清理和明确清除按钮，不存验证码答案、操作令牌或其他私密内容。

## A07：独立 SSR 页来源和状态标签不完整（P3）

根因：public_reading.py 仅将 operator_summary 显示为管理者摘要，其他 provenance 都降为公开记录；状态、动作和生命周期 from/to 直接转义原值。SPA 有双语字典，SSR 没有复用。

触发条件与概率：直接打开非摘要详情，条件概率必现。

修复风险与安全边界：低风险。共享只读双语显示字典，未知值保留安全原文并标明未验证；不能补回 reason、工具输入或私有目标。

## A08：独立 HTML/sitemap 未进入合同清单（P3）

触发条件与概率：使用 OpenAPI 生成客户端、路由白名单或合同差异检查时触发；纯浏览器部署不触发。

修复风险与安全边界：低风险。补单独公开 Web 路由清单，明确它们不是 JSON API，不增加 /api 鉴权旁路，也不把 sitemap 变成证据模块。

建议：可暂缓，不需要为了补 Web 清单改变 APIRouteContract 现有角色/版本语义。补独立 Web 路由合同，测试 kind/id/lang、成功和拒绝状态、no-store、响应上限、canonical 与 sitemap 完整性；OpenAPI 可作为选项，不要求伪造版本化 HTML API。

## A09：整仓回归仍有短 deadline 失败（P2）

根因与既有证据：最终日志 .runtime/public-remediation-full-9e461fe.xml 记录 2484 passed、56 skipped、1 failed、0 errors。失败是 tests/test_m42_p2_06_p2_07_provider_security.py::test_embedding_response_stream_has_hard_body_time_and_token_bounds，50ms 合成慢流没有触发预期超时；同模块 5 项和单项复验通过，但不能替代整仓零失败。只读诊断显示 Windows Python 3.11/3.12 的 time.monotonic 使用约 15.625ms 分辨率 GetTickCount64，perf_counter 为高分辨率 QPC；约 60ms 流可能被 monotonic 读成 47ms。公开预算也使用 monotonic，虽为秒级。

影响：平台间 timeout 可能偏早或偏晚，影响供应商流读取、公开查询和结果未知处理。不能把单项通过写成整仓门禁通过，也不能归因于机器慢后忽略。

触发条件与概率：Windows 几十毫秒 deadline 跨计时刻度且存在调度抖动时触发；秒级生产请求影响较低，严格短超时测试条件概率更高。Linux 本轮未验证。

修复风险与安全边界：中高风险。应统一跨层绝对 deadline 和高分辨率 monotonic 时钟，验证线程取消、计费和未知结果；不能只增加 sleep、只换一层时钟或放宽断言。

建议：立即单独立项；修复前保留该失败，不能宣称整仓零失败。

## A10：预算仍是未完成的容量合同（P2）

根因：public_archive.py 设置每请求 2 秒、250000 VM steps、128MB 读/解压和 sitemap 1000 条上限；冷段另有每页 2 段、5000 事件、64MB 限制。这些边界阻断资源失控，但没有全文索引、分区 sitemap、段游标或异步已验证索引。

影响：数据增长后合法页面可能稳定返回 503；大文本搜索和 sitemap 会在完整响应前耗尽预算。预算是应用检查点，不是操作系统抢占，单次解压/JSON 可能在检查点间超出墙钟。

触发条件是全文搜索、跨冷段、超过 1000 条 sitemap、慢盘或锁竞争；小实例低，大型长期实例随数据增长上升。修复索引/异步投影会增加 schema、迁移、归属、备份和恢复风险，不能取消预算或把 503 改空列表。

建议：与 A02 合并规划只读、主体隔离、可验证索引和分区 sitemap。现有 public-contract-v2.md 已明确 1000 条和段数限制，不得误报为未文档化；缺的是更大规模交付和实际容量矩阵。2 秒属于协作检查点，128MB 是逻辑读取/解压量，不是整个进程 RSS 的 128MB 上限；默认最多 32 个 HTTP worker，也未建立公开解密专用总并发/内存准入。本次未做真实大负载 RSS 测量，不给出“必定 OOM”的结论。

## 其余完成度缺口和优化建议

### C01：返回上一批只恢复批次起始页（P3，暂缓）

根因：app.js:718 的 batchPaths 只保存起始 URL，previous 重新请求默认 20 条，未保存上次已展示范围的终点。450 条合成阅读到第三批后返回上一批，实际是首 ID=200、20 条、batch=2、nextCursor=220；不是之前显示的完整 200 条。修复风险低中。用户仍可加载更多到达全部历史，不能称历史不可达或数据丢失，但需再次点击约九次才能回到原批次末端。

触发条件是超过一批再返回；条件概率必现。可暂缓，优化为保存每批的游标/范围而非正文，再在严格并发/字节上限内重读，或将按钮文案明确为“返回上一批起点”。必须继续重查撤回可见性，不缓存已撤回正文作为权威内容。

### C02：独立阅读页缺手动主题与返回上下文的一致体验（P3，暂缓）

根因：SSR 无脚本也不读 localStorage，html 没有 SPA 的 data-theme。共享 CSS 已有 prefers-color-scheme 暗色规则，因此独立页会跟随系统；缺的是 SPA 手动覆盖主题的连续性。阅读页返回仅有类别 hash，不显式带原列表状态。修复风险低中，SSR 仍应无脚本并维持安全 CSP。

影响：用户手动选择与系统不同的主题后打开文章，会恢复系统主题；同一浏览器已有 localStorage 语言偏好一般仍被 SPA读取，不应误报为所有英文返回都变中文。直接用 lang=en 查看 SSR 时，返回链接没有把该选择带回。时间筛选、cursor 和批次明确不在返回 URL。手动主题与系统不同时从静态代码可确定差异，未对所有浏览器做视觉验收。

建议可暂缓：SSR 添加明确 theme/lang 参数或 CSS 系统主题规则，返回 URL 用允许字段描述列表上下文；不要通过注入任意 HTML/脚本统一显示。与 A06 导航修复一并验收会减少重复工作。

### C03：正文结构是有界子集，目录/标题层级尚未完整（P3，暂缓）

根因：Python/JS 各自解析三种 # 标题；TOC 最多100项，SSR h1 下的首个 # 直接变为 h3（SPA 上方 h2 时该映射合理）。结构支持段落和标题，未支持列表、引用或更完整语义，也没有明显说明第101个标题起不在目录中。风险低，修复风险中，不能为了 Markdown 完整性开放 raw HTML、图片或任意 URI。

触发条件：长文有100个以上标题或用户使用列表/引用语法时，目录子集/纯文本确定出现；普通短文不受影响。当前合同已说明100项和受限标题，不将此限制算作解析安全漏洞。

建议可暂缓：公开说明语法子集，独立页根据 h1 自适应正文标题层级；目录显示截断提示。若增加列表/引用，应使用有界安全解析与 DOM/HTML 双实现一致性测试。现有转义和无脚本渲染继续保留。
