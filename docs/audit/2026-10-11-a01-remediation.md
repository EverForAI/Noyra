# A01 访问日志隐私与控制字符修复

应用基线：`5c9a3a78a9840ebc5285e6ab4881afc3780a2f36`；审计记录：`b9514af`。

## 范围与根因

仅处理第四轮审计 A01 与同根因子问题 A01b。A02、A03、A04、E01、E02
保留在原审计报告，本轮不修复。聊天删除继续禁用。

原 HTTP handler 覆盖标准库 `log_message()` 后，直接将格式化的原始请求行
交给应用 logger。普通相对 URL 的搜索词不匹配既有绝对 URL 脱敏规则，且覆盖
跳过了标准库的控制字符转义。路径里的窗口 ID、webhook 凭据和未知路由也没有
内容白名单。仅删掉 query 或增加秘密正则无法覆盖根因。

nginx 示例未明确访问日志格式，会继承可能包含原始请求行的主机配置。nginx
错误日志亦可能带原始 target，不能用自定义 access_log 格式过滤 error_log。

## 实施顺序与安全边界

1. 用真实临时 HTTP 服务复现授权/未授权搜索、路径与协议错误的日志泄露。
2. 在 handler 的 `log_request`、`log_error`、`log_message` 源头只交付固定事件、
   白名单方法、现有 API 合同的固定路由模板和数值状态。动态参数与 query 不进入
   logger，未知路由归为 `unmatched`；未知方法归为 `UNKNOWN`。解析失败尚无可信
   路由，不使用原始错误字符串或前一次连接请求的路径。
3. nginx 示例在 http 上下文定义安全格式，HTTP/HTTPS 两个 server 显式覆盖
   access_log。两者不记录无法字段过滤的原始 error_log；状态/耗时仍在访问日志，
   路由与协议错误/超时事件仍在应用日志。未改变其他虚拟主机的全局错误日志。
4. 执行日志、真实聊天请求、鉴权/会话、webhook、请求预算与部署合同回归，审阅
   差异和静态检查后本地提交。

日志分类只服务诊断，不参与实际路由、鉴权、CSRF、请求预算或响应内容。使用现有
API 合同生成路由模板，不引入 schema、依赖、资源计费或聊天数据迁移。现有网络
与云 SDK 的日志/异常/history 脱敏边界保持原合同。测试只用合成凭据、隔离数据库
和 loopback，不读取生产聊天、日志或密钥，不清理历史日志，不部署生产。

## 验收要求

- 存在/不存在窗口、授权/未授权、中文/URL 编码搜索仍返回原合同的结果和状态；
  默认及新增日志 handler、LogRecord 内容都不含原文、查询词、私密 ID 或令牌。
- 任意未知路径、webhook 路径、未知方法、坏协议版本和原始控制字符不进入日志。
- 正常状态、固定路由、解析错误和超时仍可诊断；长请求和连接复用不会改变请求处理。
- nginx 的安全格式不包含原始 target、query、headers 或客户端任意方法字符串；
  HTTP/HTTPS 均覆盖继承的日志。实际代理验收与生产历史日志仍有环境边界。
