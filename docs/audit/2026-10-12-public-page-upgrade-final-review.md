## 范围与结论

用户采纳公开页面升级建议，明确暂不实施「可核验性与公开证据」，并继续不增加聊天删除。P01–P07 的本地实现、专项、真实浏览器及最终整仓回归均已完成。本地验收达到本轮交付要求；56 项环境跳过、锁定依赖 CI 和 Linux/线上发布门禁仍须分别验收。

本轮把原先几个平铺列表改为独立的公开运行档案，包括首页、时间线、文章详情、生命周期、公开目标、项目、预测、研究、睡眠、交流、帖子、投稿与关于页面。新领域只展示管理者手写、明确审核的独立摘要，不自动公开内部资料，不把审核摘要标为 Noyra 原话。原项目介绍静态站保持独立。

没有增加公开证据页、证明、manifest 或匿名导出。修复 schema 93 在既有管理员运行导出中的归属图是私有导出兼容工作，不是公开证据模块。没有新增聊天/记忆删除接口、按钮或删除任务，也没有生产数据变更、付费调用、真实通讯或资金操作。

## 数据、隐私与连锁影响复审

### 匿名读取

`PublicArchive` 使用显式公开字段和当前主体过滤，没有调用管理员私有状态、目标或项目序列化视图。日记沿用既有公开内容与完整性验证；行为仅读取最新公开修订；交流只读 `outgoing/public:*`，不返回入站正文或对方身份；帖子只读已审核发布内容；生命周期只返回状态枚举与时间，不返回内部理由、来源和因果链。

新增目标等摘要由 `public_publications` 独立存储。匿名返回值没有 `source_id`、管理员身份、修订历史或内部对象正文。`operator_summary` 标签同时在列表与详情显示。合成隐私哨兵测试使用真实日记、睡眠、行为、入站/出站交流与帖子存储，确认私有判断、输入、结果、反思、对方身份及审核理由没有进入 v2 时间线或总览。

列表不携带完整正文，避免多个长日记使整页超过 HTTP 上限；匹配分类的详情请求重新检查可见性和完整性。撤回后同一详情 ID 返回空结果，前端重读失败清除旧正文。匿名读取省略管理 Cookie，使用 no-store，输入校验限制查询字段、文本长度与页大小。

### 发布与撤回

管理写入沿用操作员鉴权和 Cookie 会话 CSRF。未经明确审核确认不发送发布请求；服务端同样要求 `confirm_public=true`。创建、编辑、撤回使用当前主体与修订版本，陈旧修改返回 409。相同内容的网络重试不追加重复修订；类型与来源不能在编辑时静默更换。任何绑定的来源都先验证当前主体归属，但不会因此公开来源正文。

修订元数据使用不可修改/删除触发器。撤回停止本站展示，不删除原始记录，也不能消除访客已保存的副本，界面在发布和撤回时说明这一点。管理列表刷新不覆盖编辑中的草稿版本；退出清理新模块的内容、草稿与版本身份，旧会话迟到响应不能写入新会话。

### 迁移、恢复与私有导出

schema 92→93 仅追加公开摘要表、索引与触发器，并保留原私有事件，不发布历史内容。schema DDL 与结构指纹均更新为固定值，不放宽未知结构拒绝。已有 schema 71 与其他历史数据库专项覆盖升级和恢复基础契约；本轮没有修改加密备份或删除恢复策略。

综合复审曾发现新增 schema 未注册到私有运行导出的显式归属图，导致既有管理员导出在 schema 93 必然失败。两项现有专项复现后已从根因修复：摘要表按主体归属，修订按摘要父表归属。双主体专项确认只导出当前主体的摘要及其发布/撤回修订；未知 schema、未知表、外键异常和跨主体拒绝规则保持有效。

### 既有 OpenAPI 引用债务

严格 YAML 解析、183项操作清单匹配及 operationId 唯一性通过，本轮新增的内部引用全部可解析。不过整份 OpenAPI 仍有五种未定义的旧响应引用：`LengthRequired`、`NotImplemented`、`RateLimited`、`RequestEntityTooLarge`、`RequestTooLarge`。逐项对比实施基线的 `docs/api/openapi.yaml` 确认这些引用在本轮之前已经存在；不能将新引用检查通过表述成全文件引用完整。

此项记录为既有 P2 文档契约问题：根因是旧路由引用与 `components.responses` 定义没有同步；当严格解析器、SDK 生成器或文档工具遍历相关路由时会拒绝或产生缺失响应说明。完整引用校验能确定复现，运行中 HTTP 的状态处理不由这些 YAML 引用驱动，因此未发现它改变本轮匿名权限或服务返回。补齐已实现响应的定义通常是低风险修复，但必须核对实际错误结构和所有别名，避免只是让解析器通过却描述错协议。建议在契约维护中单独修复，不作为本轮公开页面交付的阻断，也不在本轮扩大代码修改范围。证据为 `.runtime/verify-public-openapi.py` 与 `.runtime/public-upgrade-openapi.json`。

## 发布与后续边界

本轮完成本地代码和本地验证，不推送、不合并、不部署。线上仍使用部署时的版本，不会因为本地页面完成而自动升级。Linux/systemd、真实云环境、平台通讯、资金与精确 SHA 的外部发布门禁没有在本地替代验收；不得把相关跳过项目或历史生产 soak 当作新提交的线上证据。

新公开摘要需要管理者在管理台逐项批准后才会出现，未配置的分类显示明确空状态。这是公开许可边界，而不是读取私有数据的失败。公开页面交付不代表项目先前其他审计问题全部关闭。
