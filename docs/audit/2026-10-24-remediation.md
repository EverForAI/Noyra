# 2026-10-24 独立审计问题的分模块修复

基线：`0a0c031dc6cdf4e08d3b6b5b0430a9503dce7aa5`。对应报告：`2026-10-24-independent-readonly-audit.md`。

## 顺序与完成标准

| 模块 | 对应问题 | 工作范围 | 主要安全边界 |
| --- | --- | --- | --- |
| 1. 认知输入与记忆 | A01、A06 | 有界检索查询、先判断来源再召回、长消息队列回归 | 保留正文和授权会话；不把技术错误伪装成主体拒绝；不新增模型权限。 |
| 2. 外部交付候选 | A02 | 对合格候选应用批次限制，排除内部页面交付及不可用来源 | 保留原 bot/app 绑定；不能为了推进队列换账户代发；不虚报 delivered。 |
| 3. 意向撤回 | A03 | 关联意向与邀请，筛选和消费/提交时检查撤回 | 并发撤回不能伪造主体决策；已发生调用仍正常记账；不改既有支付。 |
| 4. 幂等准入 | A05 | 验证既有收据后才做新建准入，保持输入及归属校验 | 同键不同内容仍拒绝；重试不新增工作流副作用或付款；容量检查保持原子性。 |
| 5. 通知与机会分页 | A04、A07 | 先按通知条件筛选、稳定分页、UTF-8 预算、页面继续读取 | 仅读本人或获准公开的字段；有界查询；不静默删改验收条件和金额。 |
| 6. 错误与状态解释 | A08、A09、A10 | 验证码错误、KDF 忙、真实付款状态 | 保持失败计数、KDF 上限、验证码及付款策略不变。 |

每个模块完成后：阅读完整 diff，核对正常/异常/并发和兼容路径，运行有针对性的回归，记录结果，再单独提交；通过后才进入下一模块。最后检查集成、文档、源文件变更范围及工作区。

## 全局边界

- 本次只修改和提交本地仓库；不推送、不合并、不访问或升级生产服务器。
- 所有验证使用临时数据库、合成凭据和模拟供应商；不进行真实模型付费、外发消息或链上支付。
- 优先使用已有稳定标识和事务，不为了修复局部问题扩大权限或修改不可变历史归属。
- 若需要调整契约，保留已有调用方式可用，更新 API 文档与调用端并添加兼容验证。
- 不承诺无法验证的“绝无次生问题”；以回归、复审与已知限制记录结果。
