## 2. 规划及取舍

修复顺序为：运行租约/最终发布与发送边界 → 迁移整体期限及鉴权前资源预算 → XML 解析边界 → 签名用途约束 → HTTP 权限审计放大 → 有确定性证据的 P3 兼容修复。

共同约束：

1. 不将网络 I/O、临时文件写入/fsync、完整权限遍历置于生命周期提交锁内。
2. `accounting_scope` 仅包围已有动作/尝试的终态记账，不包围新请求、余额快照、续租、重试或文件发布。
3. 迁移激活结果不明确时保留 source fence，不能用自动解封换取“恢复可用”。
4. 不删除断言或放宽等待时间以获得通过；用真实临时文件/数据库、确定性并发事件和本机 TCP/TLS 补充回归。
5. 不猜测既有 root 目录的用途，不自动 chmod/chown 模糊的历史控制目录。

风险等级沿用原报告：P1 为高优先级正确性/边界问题，P2 为受触发条件限制但应修复的问题，P3 为低优先级兼容性或测试可靠性问题。“修复风险”指改动可能引起回归的风险，不是漏洞风险，也不因本地测试通过而自动归零。

## 4. 实施细节、影响与触发条件

### A01：文件实际发布与运行租约

**原触发条件**：已授权的写文件动作完成临时内容准备后，运行实例被暂停、隔离或迁移栅栏失效；原代码仍可能替换目标，之后动作终态又被租约拒绝。

**实施**：`capability/filesystem.py` 只将发布前授权回调、最终租约断言、rename/replace 和本地已发布标记放入 `current_commit_scope`。准备、写入、fsync 都在锁外。授权回调可能重入触发失效，因此回调之后再次断言。`capability/tools.py` 使用独立、窄范围终态记账。

**效果**：失效先发生则原文件不变，动作 failed；发布先完成则后续暂停不会把真实成功伪装为未执行。不能撤回在暂停之前已经完成的合法文件替换。

**回归控制**：真实跨线程暂停/发布排序、回调内重入失效、原目标内容、终态和临时文件清理均有断言；原有句柄相对路径、Windows 重解析点和 grant 校验不删除。

### A02：迁移完整请求期限及安全关闭

**原触发条件**：迁移的 DNS、连接、TLS、响应头或滴流响应体迟滞；空闲 socket 超时不足以约束完整请求。源端封锁和服务关闭可能被拖住。

**实施**：`migration/http_executor.py` 将完整同步请求纳入 `call_sync_http_with_deadline`，复用全局最多 4 个后台 HTTP worker；工作线程也携带绝对 deadline，连接及地址重试消耗同一剩余时间。每请求有取消钩子，DNS 返回后、显式连接后和读取结果后均检查；过期 DNS 结果不能继续发请求。主动关闭后拒绝新请求。

**实现时补充发现并修正的回归风险**：HTTP/1.0 / `Connection: close` 的 `getresponse()` 会把 socket 从 connection 分离；只读取 `connection.sock` 会漏掉正在读 body 的 socket。此外 Windows 的 socket `makefile()` 持有 I/O 引用，普通 close/shutdown 不能可靠立刻解除阻塞读取。现在连接后保留实际 socket，取消时 shutdown，再通过 detach 后关闭原生句柄；随后 buffered-file 清理不会误关复用的描述符。显式连接后关闭 `auto_open`，避免取消导致库隐式重连。响应在工作线程 finally 中明确关闭。

**关闭边界**：`service.py` 先取消迁移 transport，再等待迁移 worker。没有为了缩短关闭而释放仍被快照/本地文件操作使用的数据库/进程所有权。网络等待受整体期限约束；不宣称任意本地文件系统 I/O 有硬上限。OS DNS 本身不可强制终止，但迟到 worker 数量有界且不得在过期后发送。

**回归控制**：真实滴流总体超时、迟到 DNS 不发送、本机正常响应、HTTP/1.0 与 HTTP/1.1 的 TCP/TLS body 阻塞取消、worker 退出、关闭后新请求拒绝。目标激活异常仍保留 source fence，未改变协议对账语义。

### A03：网页读取最终发送授权

**原触发条件**：排队、DNS 或建连期间撤销 web grant、停用/更换 source 或使运行租约失效。

**实施**：`world/source.py` 支持发送前回调，在入口、httpcore `send_request_headers.started` 及读取后重检租约。`capability/tools.py` 从存储重新读取 source，并重验证本次已经计费的 grant，不重新调用 use；接收后再次检查，不把失效结果作为成功文档提交。已有动作失败/成功终态用窄记账区结清。

**保留边界**：原 DNS/对端地址约束、响应限制、禁止重定向等防线保留。不能召回在撤销完成之前已经发出的字节；本轮针对的是发送前最后重检，不宣称把远端网络系统纳入本地数据库原子事务。

### A04：钱包只读 RPC 与终态记账

**原触发条件**：`eth_chainId` 与余额 RPC 之间或排队/发送期间撤销网络、资产、地址配置或暂停运行。

**实施**：`wallet/rpc.py` 固定初始网络/资产/地址记录；每个请求前、httpcore 请求头 trace 和结果返回前重新读取并比较。配置变更即拒绝，不继续查询。同步后台 worker 继承原 ContextVar 租约。

`wallet/acquisition.py` 另外处理暂停后错误记账也被旧租约阻拦的问题：只对已领取尝试执行 `mark_unknown`；不把续租、成功余额快照或新请求放进 accounting。若尝试已被别人接管，只读返回现状，不在失效会计区触发 recover/retry。

**验证**：首个 RPC 返回时暂停/撤销后不发第二个 RPC；runner 在读取、renew、complete_success 三处失效均不会留下成功余额快照，并验证尝试终态及完整性哈希。未知结果维持保守预算和人工重试语义。

### A05/A09：共享有界 XML 解析

**原触发条件**：微信入口的注释伪标签绕过声明过滤，或搜索 RSS 的 UTF-16 等编码绕过 ASCII 字节检查，导致不可信 DTD 进入解析。

**实施**：新增 `core/xml.py`，通过 TreeBuilder `doctype` 回调拒绝 DTD，在 start/data 建树期间累计节点、深度、文本预算；正常 CDATA 继续支持。微信和 RSS 均使用此实现，保留既有输入长度与结果校验。

**边界**：不是简单地移动/删除鉴权前解析；加密微信封套协议仍需有限解析。拒绝含 DTD 的旧输入是有意收紧。不同编码、注释伪装、CDATA、深度/节点/文本超限均有测试。

### A06：目标代理鉴权前资源预算

**原触发条件**：可达 loopback 代理或运维转发入口，未鉴权客户端建立大量连接、缓慢发送请求头/体。

**实施**：`scripts/noyra-migration-agent.py` 新增有界 HTTPServer，超出 16 个工作连接直接关闭；槽位在 finally 释放。`DeadlineRequestReader` 令请求行、请求头和请求体共享 30 秒绝对期限，并限制总读取字节。拒绝 Transfer-Encoding 和重复/缺失 Content-Length。

**兼容取舍**：代理改为 HTTP/1.0 单请求/连接，防止 keep-alive 占槽；既有迁移客户端原本逐请求建连接，HMAC、路由、body 协议不变。此期限约束网络读取，不强杀已经鉴权的本地恢复/激活工作。

### A07：签名器端用途绑定

**原触发条件**：已持有有效 signer bearer 的调用方可以请求任意 personal message，且同一地址在其他系统也承担签名身份。

**实施**：`signer_service.py` 严格解析 JSON，字段集合必须精确匹配迁移 challenge；域固定为 `noyra-migration-wallet/v1`；signer_id 必须匹配当前服务；任务/目标标识有类型、长度和控制字符约束；manifest_digest/nonce 必须为 64 位小写十六进制。服务端重新生成 canonical JSON，仅签名该值，拒绝额外字段、非规范编码、通用文本及其他域。

**边界**：保持合法客户端原有 canonical challenge 协议，不引入未经端到端设计的到期字段。签名器仍不查询迁移任务数据库，不能单凭本轮改动证明任务真实存在；目标端现有上下文验证仍必要。本轮不是通用钱包签名 API，也不是 bearer 泄漏防护的替代品。

### A08：HTTP 高频入口改用后台权限审计

**原触发条件**：启用 required 静态存储保护时，匿名 readiness/部分 API 可反复触发完整私有目录权限扫描，工作量随目录规模增长。

**实施**：`core/at_rest.py` 新增 HTTP 专用 request_health / require_request_ready；原 health / require_ready 的严格同步全量校验保留。启动严格校验后建立权限快照，首次 HTTP 检查启动一个共享后台 monitor，扫描结束后间隔 1 秒刷新。`/health/ready` 和 API 静态存储准入改走新路径；普通 `/health` 原有的短缓存及严格诊断扫描保留，并非删除所有 HTTP 诊断全扫。HTTP 每次仍实时检查卷、密钥及根目录身份/安全元数据。

**安全性与可用性取舍**：

- 权限快照最多有效 5 秒，时间从扫描开始而非结束计；无快照、过期、扫描失败或根目录身份/安全元数据变化均拒绝请求。POSIX 的 uid/gid/mode 纳入逐请求签名；Windows 根目录 ACL 不能由普通 stat 完整表达，和嵌套 ACL 一样依赖后台审计的新鲜度窗口，不能承诺其即时失效。
- 不把目录 mtime/ctime 当成权限 epoch：普通 SQLite WAL 创建/删除会改变这些时间，否则正常流量会被持续 503。
- POSIX 后台扫描设 4 秒/100,000 条目的检查预算；Windows 后台 ACL 扫描有 100,000 条目上限并保留子进程超时。超预算不是忽略尾部后放行，而是不可用。
- 嵌套权限变化不是逐请求即时检查，存在最多 5 秒的陈旧授权窗口；实时卷/密钥/根目录检查不会被有效快照覆盖。这是显式一致性取舍，不能描述为“所有权限变化即时检测”。
- 这是消除匿名请求与全树遍历的线性放大关系，不宣称所有平台探测都零成本。原遍历仍有每目录排序，超大单目录可能占用较多内存；严格启动全扫也保留。更大型部署若连续超预算会 fail-closed，需要单独设计分片/增量权限审计，而不是放宽本轮安全策略。
- close 停止 monitor 并使 HTTP 快照不可用；不遗留每请求新建的扫描线程。

**验证**：30 次重复请求仅共享同一个受阻扫描；pending/过期/关闭状态拒绝；新鲜快照无法覆盖实时卷、密钥、根身份失败或已确认的不安全扫描结果；WAL 正常变更不导致根签名抖动。原静态存储及真实平台权限测试继续执行。

### A10/A11：旧传输兼容接口

**A10 根因与修复**：最后短块时 next_chunk × chunk_bytes 大于实际长度；改为与总长度取小值，并补齐回执数值/块数边界校验。覆盖空文件、短文件、整块、尾短块及多块。

**A11 根因与修复**：原先直接截断/写目标，全部完整性验证太晚；现在在同目录创建私有临时文件，解密、块数、总长度、总哈希、尾部数据验证全部通过后才 os.replace。各种损坏及错误回执既不破坏旧文件，也不留下未验证新目标，临时文件清理。成功时仍允许按旧接口语义替换目标。没有顺带重构传输协议、增加远端自动重试或更改新迁移通道。

### A12/A13：保守权限兼容及测试隔离

**A12**：`core/runtime.py` 新建 migration 父目录时显式指定 0700，再创建 source 子目录；避免 root 普通运行时隐式生成 0755 中间目录，被误识别成特权安装布局。没有改动布局识别条件、没有宽松接受不合规安装目录，也没有对既有目录自动 chmod/chown。**历史 root/0755 普通目录的自动分类修复延期**；需要结合部署证据人工判断，不能盲目改权限。本轮全量回归继续验证安装/备份边界。

**A13**：`test_migration_storage_boundary.py` 的真实服务 UID 子进程同时重定向 STORAGE_IDENTITY_PATH 和 BACKUP_STORAGE_IDENTITY_PATH 到测试临时的不存在路径；避免误读宿主受限 `/etc/noyra`。没有修改宿主配置，也没有模拟掉服务 UID 或放宽生产权限检查。

- Windows：Python 3.12.10，真实本机 socket/TLS、文件与平台边界；解释器为项目外侧工具目录。
