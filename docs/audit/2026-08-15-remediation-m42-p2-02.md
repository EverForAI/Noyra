# M42 P2-02 Behavior Reconciliation Remediation

Date: 2026-08-15

## Scope

This remediation closes the behavior-log append-only finding from the read-only audit. It keeps
the original `behavior_logs` row as the first observed outcome and records later reconciliation
as a separate, immutable revision. It does not change the action state machine beyond preserving
the existing reconciliation transition.

## Changes

- Schema 33 adds `behavior_log_revisions`, a subject- and action-scoped hashed revision sequence
  with a stable SHA-256 state hash, append-only update/delete triggers, and a sequential revision
  check. At most one reconciliation may follow an original `unknown` revision, and stable public
  fields cannot change across that boundary.
- Legacy behavior rows receive a baseline revision inside the schema 33 migration transaction. A
  baseline reflects the bytes that existed before the migration; it does not claim to reconstruct
  an earlier unknown outcome that was already overwritten. A current-schema database with a
  missing revision fails closed instead of silently repairing the evidence gap.
- `ActionLedger.reconcile_unknown()` updates the action as before, but appends a revision instead
  of changing the original behavior row. Behavior-log reads return the latest derived projection
  together with `original_*` fields so operators can distinguish current status from first evidence.
- Public behavior projection and authenticated runtime export include the latest projection and the
  complete revision table. Integrity verification checks ownership, contiguous numbering, baseline
  equality, status alignment, and every revision hash.

## Evidence

- `tests/test_m42_p2_02_behavior_reconciliation.py` proves that reconciliation preserves the
  original row, appends a second revision, rejects direct row/revision tampering, and verifies the
  hashed revision sequence.
- The same test proves runtime export coverage for both the original `behavior_logs` row and the
  complete `behavior_log_revisions` sequence.
- Focused P2-02 tests: `5 passed`.
- M41 targeted smoke and large profiles: `53 passed` each; full repository pytest: `326 passed`.
- Deployment audit: `40 passed`, `72.07%` coverage. Ruff, format, Mypy, compileall, pip check,
  and production-lock `pip-audit` passed.

## Residual risk and follow-up

Existing databases that predate schema 33 cannot recover an unknown value that was already
overwritten; migration preserves the state that is actually present and labels it `legacy
baseline`. New reconciliations are append-only and hash-checked. Provider-specific unknown
delivery contracts remain open under P2-04 and P2-05. Windows gates ran locally; the Ubuntu entry
point remains reproducible but could not be executed because this machine has no Ubuntu distribution.
