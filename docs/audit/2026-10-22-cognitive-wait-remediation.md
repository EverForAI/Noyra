## 永久修复细节

### 等待所有权与并发

- ObservationStore.mark 的 analyzed/rejected 更新与等待取消在一个 BEGIN IMMEDIATE 中。
- SleepEngine 接受反思计划（包括 bounded fallback）时关闭反思等待；complete/failed 再次覆盖终态。
- 登记 unavailable 先重新读取同主体父状态，晚到失败不能复活终态用途的等待。
- current hash / 修订 hash / 状态序列校验；取消追加 cancelled 修订，保留 first_waited_at、retry_count、next_retry_at。
- 一次事务里父更新、等待更新、修订任一步失败全部回滚，不“修正”为模型成功。
- 单条历史超过 1,000 修订时拒绝自动收口，需要专项核验；有界检查不静默截断证据。

### 历史工具

python -m noyra.cognitive_wait_maintenance 默认 mode=ro+query_only+BEGIN，读取 WAL，不使用 immutable。
每批最多扫描 100 条；锁等待 200ms、SQL 工作预算 2 秒（不是磁盘 IO 硬时限）。
应用必须显式 --apply、匹配 --expect-plan 和 --reason；不初始化/迁移数据库，核验 schema 与父状态证据。
应用串行化重新预览，状态变化整批拒绝；同 purpose 在其他池/页的记录不顺带修改。
事务内追加 operator 审计事件；重复旧计划拒绝，重新预览无候选时为空操作。
父缺失、哈希/历史异常不自动清理。详见 deployment/cognitive-wait-maintenance.md。

### 后台与测试

- 真正的主服务只读 getter 同时用于详细诊断与轻量摘要；单独 HTTP 服务默认认知未创建。
- 正式测试区分 lifecycle 409、inactive 409、state conflict 409、authorization 403、budget 429、
  invalid fields 400、provider/structured output 502；保留授权、费用与单次尝试约束。
- 摘要按资源组/池/模型提供最近调用样本，分开管理员测试与其他调用，不能当供应商账单或业务完成数。
- waiting/cancelled 最近最多 100 条样本分终态残留、历史取消、未发现终态证据的等待及父缺失；
  全量池计数另有 recorded/terminal/missing/cancelled 字段。查询超限为 unknown/unavailable，不显示假零。
- 未知原因只输出有界白名单分类，不返回原始异常/提示词/响应/密钥。
