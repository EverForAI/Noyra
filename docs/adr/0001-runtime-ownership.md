# ADR-0001：自研 Noyra Runtime，复用基础库而非采用助手型 Agent 框架

状态：已接受  
日期：M1

## 背景

Noyra 不是面向用户任务的助手。其核心流程是持续事件、状态变化、情绪因果、自主目标、睡眠和隐私，而不是用户任务分解和工具调用。

OpenClaw、Hermes、LangChain、LangGraph、CrewAI 和 AutoGen 等项目可以提供工具调用、消息渠道或工作流能力，但它们的核心抽象大多以用户请求和任务完成为中心。

## 决策

Noyra 自行实现：

- Supervisor；
- 身份连续性；
- 事件账本；
- 记忆、信念、情绪、心理和人格状态；
- 目标和使命；
- 睡眠和疲劳；
- 交互协议；
- 能力代理；
- 公开状态和行为日志；
- 评测框架。

Noyra 复用成熟基础库：

- FastAPI；
- Pydantic；
- SQLite；
- HTTPX；
- Playwright；
- Ollama 或 OpenAI-compatible API 适配协议；
- pytest、ruff、mypy；
- 后续可选 MCP 工具协议。

## 后果

优点：

- 身份和主体状态不受助手型框架语义限制；
- 可明确区分模型提案和状态提交；
- 可以从无模型测试开始；
- 更容易实现隐私、审计、睡眠和恢复；
- 未来可以把其他 Agent 当作外部工具或渠道适配器。

代价：

- 需要自行实现事件队列、状态机和工具生命周期；
- 初期开发量大；
- 需要更严格的协议和测试；
- 不能直接获得现成 Agent 框架的全部集成功能。

## 替代方案

可以在后续为 Noyra 增加适配层，接入 OpenClaw、Hermes 或 MCP 生态，但这些系统不能成为主体身份、心理和生命周期的权威来源。
