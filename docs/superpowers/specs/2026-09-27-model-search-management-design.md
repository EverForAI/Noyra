# 模型与搜索管理功能设计

## 目标

完善管理台中的模型和搜索资源配置，同时避免 API 密钥进入浏览器持久存储、数据库明文或日志。管理员应能在保存模型资源前测试当前填写的数据；供应商支持标准接口时，可以获取模型列表并选择模型；管理员还可以配置搜索供应商和研究搜索路由方式。

## 功能范围

继续使用现有的 OpenAI 兼容模型资源接口作为数据源。管理台增加“测试当前填写内容”和“获取模型列表”两个操作。这两个操作只使用当前表单数据，不创建数据库资源。已经保存的资源继续保留现有的测试、启用、停用和撤销流程。

搜索资源继续使用现有的 Brave、Bing、Tavily 和 Serper 存储及密钥保护机制。管理台增加搜索资源的创建、测试、启用、停用、撤销和脱敏状态查看。

增加按主体保存的搜索路由策略：`model_first` 优先使用模型自身的搜索能力；`api_first` 优先使用已配置的搜索 API；`auto` 由 Noyra 根据可用资源、额度和研究计划自动选择。研究流程最终采用的方法和发生的降级，继续写入现有研究审计记录。

## 模型 API 行为

未保存模型测试会使用与正式模型资源相同的地址校验、密钥格式校验、超时和响应大小限制，发送一个受限的最小聊天请求。返回内容只包括供应商状态、模型标识和耗时，不返回密钥或完整响应。

模型列表功能调用 OpenAI 兼容的 `GET /models` 接口，并限制超时、响应大小和模型数量。供应商不支持该接口时返回明确的“不支持模型发现”结果，表单仍保留手动填写模型名称的能力。

## 搜索路由行为

搜索策略按主体持久化保存，修改必须经过管理员认证并写入审计记录。三种策略影响研究计划选择的优先级。资源缺失、额度不足或调用失败时，只能降级到允许的现有方法，并记录降级原因。

## 安全与失败处理

密钥只能通过认证请求提交，并通过现有受保护的 secret 存储写入；API 返回和日志中只显示指纹或脱敏信息。未保存模型测试和模型列表请求只在当前请求内使用数据，不创建数据库记录。

所有外部请求使用现有的 HTTPS 地址校验、超时、响应大小限制和不信任环境代理设置。供应商返回格式错误时，API 返回稳定的错误代码，不泄露供应商内部响应或密钥。

## 验证范围

增加以下测试：未保存模型测试成功和失败、模型列表成功和不支持、搜索资源管理和测试、策略的持久化及权限控制，以及三种策略下的研究路由。完成后运行相关 pytest、格式和静态检查，再运行完整测试套件。
