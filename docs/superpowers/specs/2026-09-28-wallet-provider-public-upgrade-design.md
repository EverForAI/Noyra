# 钱包状态、供应商健康与公开站点升级设计

## 1. 目标与边界

本次改造覆盖四个相互关联的产品面：

1. 钱包自动付款的可观测状态、总开关和紧急暂停。
2. 模型与搜索供应商的健康统计、优先级、故障切换和冷却恢复。
3. 遥测聚合、保留周期和分批清理，控制 SQLite 长期增长。
4. 公开站点的治愈科技视觉、移动端、无障碍、加载速度和社交分享。

现有钱包生命周期、模型路由、搜索路由和管理台页面继续作为基础，不另起一套并行系统。数据库迁移使用追加式 schema 版本；旧状态和旧 API 继续可读取，新增字段提供兼容默认值。

本次不改变私钥边界，不把私钥、API 密钥或完整模型输入输出写入新的统计表，也不把自动付款默认打开。公开站点仍只展示公开投影，管理台仍通过已有 HTTPS、会话和操作令牌边界访问。

## 2. 钱包状态与自动付款控制

### 2.1 状态模型

保留 `wallet_payment_executions.status` 的现有生命周期：`signing`、`broadcast`、`unknown`、`confirmed`、`failed`。不直接扩展生命周期枚举，避免破坏已有 SQLite 触发器和恢复逻辑。

在执行记录和管理台投影中统一使用 `reason_code`（现有 `error_code` 兼容读取），支持以下固定代码：

- `insufficient_balance`：余额不足以覆盖付款金额或交易费用。
- `gas_too_high`：当前费用报价超过钱包策略允许的上限。
- `nonce_conflict`：链上 pending nonce 与本地执行发生冲突。
- `confirmation_timeout`：交易已广播，但超过确认等待窗口仍没有满足最小确认数。
- `chain_reorg`：已观察到的回执区块不再是当前链的规范区块。
- `rpc_unavailable`：链 RPC 或签名器查询暂时不可用。
- `fee_quote_unavailable`：无法取得可信费用报价。
- `broadcast_unknown`：广播结果未知，不能安全重发。
- `receipt_failed`：链上回执明确表示执行失败。

`confirmation_timeout` 仍保持 `broadcast` 或 `unknown` 状态，不自动重发；管理台显示“待人工处理”，并提供再次查询回执和受保护的重试入口。`chain_reorg` 将执行置为 `unknown`，保留旧区块证据，并要求重新确认规范链结果。所有原因码进入固定白名单，未知字符串不能写入状态投影。

### 2.2 自动付款总开关

在 `wallet_payment_policies` 增加 `automation_enabled`，默认 `0`。自动付款真正执行必须同时满足：

- `mode = automatic`；
- `automation_enabled = 1`；
- `emergency_paused = 0`；
- 单笔、每日限额和余额/观测时效检查通过；
- 现有钱包完整性、签名器和加密存储检查通过。

`conditional_confirmation` 仍可创建待确认订单，但不自动广播。关闭总开关不会取消已有订单，只阻止新的自动预留和执行；已有广播交易继续执行回执观测。紧急暂停优先级最高，暂停时所有新的自动付款返回稳定错误码 `wallet_automation_paused`。

增加管理 API：

- `GET /api/v1/admin/wallet-automation`：返回总开关、模式、紧急暂停、限额、活动执行数和需要处理的原因码计数。
- `POST /api/v1/admin/wallet-automation`：以期望版本更新总开关和模式，要求理由和幂等键。
- `POST /api/v1/admin/wallet-automation/pause`：紧急暂停，追加不可变审计记录。
- `POST /api/v1/admin/wallet-automation/resume`：解除紧急暂停，要求理由和期望版本。

原有钱包策略接口继续支持旧客户端；服务层将旧策略字段转换为新投影。管理台在首屏显示高对比度状态横幅，红色仅用于紧急暂停或存在高风险交易，绿色只表示“自动付款已开启且无阻塞”，灰色表示关闭。

## 3. 模型和搜索供应商健康与路由

### 3.1 聚合健康数据

新增统一的 `provider_health_buckets` 表，按 `subject_id`、`provider_kind`、`provider_id`、UTC 日期桶唯一。`provider_kind` 为 `model` 或 `search`。字段包括：

- `window_start`、`window_end`；
- `attempt_count`、`success_count`、`failure_count`、`unknown_count`；
- `latency_total_ms`、`latency_max_ms`；
- `last_success_at`、`last_failure_at`；
- `last_error_code`；
- `state_hash`、`updated_at`。

健康投影按最近 24 小时计算失败率和平均响应时间，并返回累计值、当前状态、冷却结束时间和数据更新时间。原始 API 密钥、请求正文、响应正文和 URL 查询凭据永不进入此表。

状态规则：

- 无请求或最近窗口内没有失败：`healthy`；
- 失败率超过阈值或连续失败达到阈值：`degraded`；
- 当前处于冷却：`cooldown`；
- 没有可用密钥/供应商或连续探测失败：`unavailable`。

### 3.2 模型路由

现有模型组 `priority`、`weight` 和密钥冷却继续保留。路由选择改为“优先级分层、同层按权重、健康状态过滤”：

1. 排除禁用、撤销和未结束冷却的资源。
2. 选择最低数值优先级的可用层。
3. 同一层按权重和历史选择次数分配。
4. 已知可重试失败切换到下一密钥或下一供应商。
5. 未知结果继续原地封锁，不能静默切换并重复产生副作用。
6. 冷却结束后只允许一个半开探测；成功则恢复，失败则延长冷却。

### 3.3 搜索路由

搜索供应商增加 `priority`、`weight`、`failure_threshold`、`cooldown_seconds` 和健康投影。现有 `model_first`、`api_first`、`auto` 仍然是上层选择；在选择搜索 API 时使用与模型相同的优先级、失败切换和半开恢复规则。管理台允许拖拽或数字调整优先级，并显示每个供应商的失败率、平均响应时间和最近成功时间。

### 3.4 管理 API

增加：

- `GET /api/v1/admin/provider-health?kind=model|search`：返回受限聚合投影。
- `POST /api/v1/admin/provider-health/{providerId}/probe`：只执行一次受限探测，不保存密钥和正文。
- 模型和搜索资源配置接口增加优先级、权重和冷却策略字段。

聚合写入与既有路由结果在同一数据库事务中完成；重复重试通过请求/尝试标识幂等，避免统计重复计数。

## 4. 保留周期与清理策略

新增配置：

- `NOYRA_PROVIDER_HEALTH_BUCKET_SECONDS`，默认 `3600`，允许 900 到 86400。
- `NOYRA_PROVIDER_HEALTH_RETENTION_DAYS`，默认 `30`。
- `NOYRA_TELEMETRY_RETENTION_DAYS`，默认 `7`。
- `NOYRA_AUDIT_RETENTION_DAYS`，默认 `365`，关键钱包安全事件不受此期限删除。
- `NOYRA_RETENTION_BATCH_SIZE`，默认 `500`。

维护任务每次只处理一个有限批次，顺序为：

1. 删除过期的成功遥测明细。
2. 保留并压缩必要失败、未知、链重组和支付安全审计。
3. 删除超出健康聚合保留期的数据。
4. 更新清理计数、最后运行时间、最早保留时间和失败原因。

涉及模型调用、研究记录或钱包执行的外键引用不会被直接删除；这些记录只在其引用链允许时清理。清理不执行无界 `VACUUM`，避免长时间锁库；管理台提供数据库大小、可清理行数和最近清理状态。

## 5. 公开站点视觉和性能

### 5.1 视觉方向

生成两套优化后的 WebP/AVIF 资源：

- 首屏背景：治愈科技场景，薄荷绿、雾蓝、暖金和微光网络，主体留出左侧文字安全区。
- 社交分享图：1200×630，使用清晰的 Noyra 标识、短标题和低噪声背景。

页面从当前的“深色大图加文字”调整为“柔和科技档案”：首屏高度降低，标题和状态卡片分层，公开记录采用清晰的时间线卡片，投稿区域使用浅色玻璃感面板。所有文字继续提供中文，英文只保留品牌和技术标识。

### 5.2 移动端和无障碍

- 375px、430px、768px 和桌面断点分别检查布局。
- 首屏图片在窄屏使用独立焦点位置，避免文字或按钮被遮挡。
- 所有按钮、输入框和动态列表拥有可见焦点、中文 `aria-label` 和状态播报。
- 支持 `prefers-reduced-motion`，关闭非必要动画。
- 保证正文、按钮和错误提示达到 WCAG AA 对比度。
- 验证码图片失败时提供刷新按钮和清晰的文字状态。

### 5.3 加载和分享

- 首屏图片使用明确宽高、现代格式和有限压缩质量。
- 首屏只保留必要 CSS/JS，档案内容和非首屏图片延迟加载。
- 增加 `og:image`、`twitter:image`、`og:title`、`og:description`、主题色和规范 URL。
- 社交图和首屏图在静态检查中验证尺寸、格式和文件大小。

## 6. 迁移、失败处理与兼容性

数据库迁移采用新的 schema 版本，旧安装自动填充安全默认值：自动付款关闭、紧急暂停关闭、供应商优先级为现有顺序、健康统计为空。迁移前后执行状态哈希校验；任何历史哈希不匹配都进入完整性降级，不自动修复。

API 仅增加字段和新路径，不删除旧字段。所有新状态和错误码都进入服务契约、OpenAPI、中文管理台映射和审计白名单。公共接口不暴露钱包余额细节、供应商密钥、模型请求正文或内部失败栈。

## 7. 验证计划

新增测试覆盖：

- 自动付款总开关、紧急暂停、版本冲突和幂等。
- 五类钱包明确状态、状态迁移、回执重组和超时不重发。
- 模型/搜索优先级、自动切换、冷却和半开恢复。
- 健康聚合计数幂等、失败率、平均延迟和最近成功时间。
- 保留策略分批清理、外键保护和清理失败恢复。
- 管理台 API 契约、状态文案和敏感字段排除。
- 公开页 HTML 元数据、响应式静态检查、图片资源尺寸和无障碍属性。
- 完整 Python 测试、Ruff、Shell 语法、差异检查和编译检查。

实现顺序为：先数据库和领域状态，再服务 API 与管理台，随后做保留任务，最后生成图片并升级公开页。每个阶段单独提交，全部通过后再决定是否部署或推送。
